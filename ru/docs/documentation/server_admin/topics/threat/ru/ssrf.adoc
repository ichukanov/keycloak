[[ssrf]]
=== Смягчение подделки серверных запросов (SSRF)

**Server-Side Request Forgery (SSRF)** — уязвимость, связанная с безопасностью, когда злоумышленник вводит сервер ({project_name}, в этом случае), чтобы обратиться к незапланированному месту назначения. В {project_name}, этот риск прежде всего связан с полями клиента, вызывающими запросы с сервера, такими как **JWKS URI**.

Если эти поля не проверяются, вредоносный администратор, скомпрометированный аккаунт или Динамическая Регистрация Клиента могут указать на внутренние сетевые ресурсы или интерфейсы (e. ., `http://localhost:8080/any`), позволяя нападающему зондировать или атаковать внутреннюю инфраструктуру с самого сервера {project_name}.

Чтобы смягчить эту угрозу, {project_name} предоставляет решение, используя <_client_policies Клиентские Политики>> с некоторыми исполнителями, такими как *Безопасный Клиентский Урис*, обеспечить базовую защиту для безопасности транспорта и подстановочных знаков, Но особенно с **Secure Client URIs Pattern**.

См. также <<dns-rebinding>> для вектора атаки, которые могут обойти проверку на основе URI.

==== Защищенный шаблон URI клиента

Этот исполнитель вводит строгую политику безопасности, проверяя URI клиента на соответствие **allowlist of patterns**. Если URI не совпадает по крайней мере с одним из настроенных шаблонов, то создание или обновление клиента отклоняется.

Он может быть использован не только для `JWKS URI`, но и для проверки всех доступных uri полей клиента, включая `rootUrl`, `adminUrl`, `redirectUris`, `webOrigins` и другие.

.Параметры конфигурации
[cols="1,3", options="header"]
|===
|Конфигурация
|Описание

|Разрешенные шаблоны URI
|Список регулярных выражений. URI клиента считается корректным **только**, если он совпадает по крайней мере с одним из этих шаблонов. Если этот список пуст или недействителен, то исполнитель блокирует **все** URI.

|Поля URI клиента для проверки
|Список конкретных полей клиента (например, jwksUri, `adminUrl`). Если оставить пустым, **все** поддерживаемые поля URI проверяются по умолчанию. Список доступен в конфигурации.
|===

==== Примеры анти-SSRF шаблонов

Для эффективного предотвращения SSRF регулярные выражения должны быть разработаны для исключения IP адресов и локальных имен хостов.

**1. Ограничение доверенных доменов**

Этот шаблон гарантирует, что сервер {project_name} взаимодействует только с официальными доменами, предотвращая использование `localhost` или числовых IP-адресов.

* **Текст:** `^https://([a-zA-Z0-9-]+\.)?mycompany\.com(/.*)?$`
* **Эффект:** Блоки пытаются использовать адреса циклов (например, `http://localhost:8080`) или конечные точки метаданных облака.

**2. Принудительное HTTPS**

SSRF часто использует незашифрованные протоколы для обхода внутренних контролей безопасности. Обеспечение HTTPS по шаблонам уменьшает поверхность атаки.

* **Шаблон:** `^https://[a-zA-Z0-9.-]+(/.*)?$`
* **Результат:** Отклоняет использование схемы «http://», которая часто используется для проверки внутренних сервисов.

NOTE: https может быть применен также с исполнителем *Secure Client Uris*, но только с подстановочными знаками и для всех URI клиента

**3. Разрешенный конкретный поставщик**

Если ваши клиенты используют JWKS URI от сторонних провайдеров, то добавьте только те домены, которые принадлежат этим провайдерам.

* **Контент:** `^https://trusted-provider\.io/.*`
* **Результат:** Все остальные домены будут отклонены для запросов JWKS.

[WARNING]
.Синтаксис регулярного выражения
====
Этот исполнитель использует регулярные выражения Java. Убедитесь, что вы правильно экранировали специальные символы (например, `\.`, чтобы указать точку). Некорректный шаблон может помешать законным обновлениям клиентов. Рекомендуется тестировать регулярные выражения в нерабочей среде.
====

[[dns-rebinding]]
==== Перепривязка DNS

Нападающий может использовать DNS перепривязку для разрешения публичного имени хоста на внутренний IP адрес, обход разрешенных списков на основе URI, которые проверяют только имя хоста в момент запроса.

Это позволяет злоумышленнику подключаться к {project_name} внутренним службам, включая конечные точки на одном узле, включение сканирования SSRF или внутренней сети в зависимости от параметров аутентификации и сетевого управления.

Для уменьшения атаки на репривязку DNS, настройте DNS резолвер, используемый {project_name} , чтобы отклонить разрешение публичных доменных имен непубличных/внутренних IP адресов.

NOTE: Это снижение уровня инфраструктуры, применяемое в DNS резолвере, а не в самом {project_name}.
