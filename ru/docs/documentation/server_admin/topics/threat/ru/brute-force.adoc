=== Жестокая сила атаки

Атака грубой силы пытается угадать пароль пользователя, пытаясь многократно войти в систему. {project_name} имеет возможности обнаружения грубой силы и может навсегда или временно отключить учетную запись пользователя, если количество неудач входа превышает заданный порог.

Защита применяется только к механизмам аутентификации, подверженным атакам с принудительной силой. {project_name} применяет его только для паролей, OTP и кодов восстановления.

[NOTE]
====
Когда пользователь заблокирован и пытается войти в систему, {project_name} отображает по умолчанию сообщение об ошибке `Неверное имя пользователя или пароль`. Это сообщение является тем же сообщением об ошибке, что и сообщение, отображаемое для неверного имени пользователя или неверного пароля, чтобы убедиться, что злоумышленник не знает, что учетная запись отключена.
====

[WARNING]
====
По умолчанию обнаружение грубой силы отключено. Включите эту функцию, чтобы защитить от атак грубой силы.
====

Чтобы включить защиту:

. Нажмите *Настройки реалма* в меню
. Нажмите на вкладку *Security Defenses*.
. Нажмите на вкладку *Brute Force Detection*.
. Выберите *Режим грубой силы*, который наилучшим образом соответствует Вашим требованиям.
+

==== Блокировка навсегда

{project_name} отключает учетную запись пользователя (блокировка авторизации) до тех пор, пока администратор не включит ее.

image:images/brute-force-permanently.png[]

*Параметры постоянной блокировки*

|===
|Наименование |Описание |По умолчанию

|Макс. число сбоев входа
|Максимальное количество неудачных попыток входа.
|30 неудач

|Проверить быстрый вход в миллисекунды
|Минимальное время между попытками входа.
|1000 миллисекунд

|Минимальная быстрая ожидание входа
|Минимальное время отключения пользователя при попытках входа быстрее, чем _Quick Login Check Milliseconds_.
|1 минута
|===

*Алгоритм Блокировки*

====
. При успешном входе
.. Сбросить `count`
.. звонить <_secondary-authn-check, `secondary authentication check (success)`>>
. При неудачном входе
.. Увеличение `count`
.. Если `count` больше или равно `Max login failures`
... блокирует пользователя
.. Иначе, если время между этой ошибкой и последней ошибкой меньше _Quick Login Check Milliseconds_
... Заблокирует пользователя на время, указанное в _Minimum Quick Login Wait_
.. звонить <_secondary-authn-check, `secondary authentication check (fail)`>>
====

[NOTE]
====
Включение учетной записи сбрасывает счет.
====

*Стратегии для установки времени ожидания*

{project_name} предоставляет две стратегии для вычисления времени ожидания: через кратные или Linear. Множество — это первая стратегия, предложенная {project_name}, так что она является стандартной по умолчанию.

По стратегии множественных чисел, время ожидания увеличивается, когда число (или количество) неудач кратные `Max Login Failure`. Например, если вы установите `Max Login Failures` на `5` и `Wait Increment` на `30` секунд, эффективное время отключения учетной записи после нескольких неудачных попыток аутентификации будет:

[cols="1,1,1,1"]
|===
|«Количество сбоев» |`Подождите` |`Макс. число сбоев входа в систему` |«Эффективное время ожидания»

|1 |30 |5 |0

|2 |30 |5 |0

|3 |30 |5 |0

|4 |30 |5 |0

|**5** |**30** |5 |**30**

|6 |30 |5 |30

|7 |30 |5 |30

|8 |30 |5 |30

|9 |30 |5 |30

|**10** |**30** |5 |**60**
|===

При пятой неудачной попытке учетная запись отключена на `30` секунд. После достижения следующего кратного числа `Max Login Failures` в данном случае `10` время увеличивается с `30` до `60` секунд.

По нескольким стратегиям для вычисления времени ожидания: _Wait Increment in Seconds_ * (`count` / _Max Login Failures_). Деление представляет собой целое дело, округленное до целого числа.

Для линейной стратегии, время ожидания увеличивается, когда «count» (или число) сбоев больше или равно «Max Login Failure». Например, если вы установили `Max Login Failures` на `5` и `Wait Increment` на `30` секунд, эффективное время отключения учетной записи после нескольких неудачных попыток аутентификации будет:

[cols="1,1,1,1"]
|===
|«Количество сбоев» |`Подождите` |`Макс. число сбоев входа в систему` |«Эффективное время ожидания»

|1 |30 |5 |0

|2 |30 |5 |0

|3 |30 |5 |0

|4 |30 |5 |0

|**5** |**30** |5 |**30**

|**6** |**30** |5 |**60**

|**7** |**30** |5 |**90**

|**8** |**30** |5 |**120**

|**9** |**30** |5 |**150**

|**10** |**30** |5 |**180**
|===

При пятой неудачной попытке учетная запись отключена на `30` секунд. Каждая новая ошибка увеличивает время ожидания в соответствии с значением, указанным при приращении ожидания.

Стратегия линейки использует следующую формулу для вычисления времени ожидания: _Wait Increment in Seconds_ * (1 + `count` - _Max Login Failures_).

*Постоянная блокировка после использования алгоритма временного блокирования*

====
. При успешном входе
.. Сбросить `count`
.. Сбросить счетчик `temporary lockout`
.. звонить <_secondary-authn-check, `secondary authentication check (success)`>>
. При неудачном входе
.. Если время между этим сбоем и последним сбоем больше чем _Failure Reset Time_
... Сбросить `count`
... Сбросить счетчик `temporary lockout`
.. Увеличение `count`
.. Вычислите `wait` в соответствии со стратегией скорой силы, определенной (см. ниже Стратегии, чтобы установить время ожидания).
.. Если `wait` меньше или равно 0 и время между этой ошибкой и последней ошибкой меньше _Quick Login Check Milliseconds_
... установить _Minimum Quick Login Wait_
... установите `quick login failure` в `true``
.. если `wait` и `Maximum temporary Lockouts` больше 0
... установите `wait` на самый маленький из `wait` и _Max Wait_ секунд
.. если `quick login failure` `false`
... Увеличить счетчик `temporary lockout`
.. звонить <_secondary-authn-check, `secondary authentication check (fail)`>>
.. Если счетчик `temporary lockout` превышает `Maximum temporary lockouts`
... Постоянно блокирует пользователя
.. Иначе
... Временно блокирует пользователя в соответствии со значением `wait`
====

[NOTE]
====
`count` не увеличивается, когда учетная запись временно отключена для выполнения неудачного входа.
====

==== Вторичная блокировка Аутентификации

Когда этот механизм блокировки включен, он действителен для всех режимов перебора.
Механизм включен, когда для «Максимально допустимых отказов вторичной аутентификации» установлено значение не нулево. По умолчанию он отключен (`0`).

Если превышено максимальное количество неудачных попыток авторизации, аккаунт заблокирован навсегда. Это поведение предотвращает атак на вторичные аутентификаторы, которые на самом деле могут быть принудительно (в настоящее время только OTP), когда злоумышленник уже угадал пароль. Разумное значение может быть установлено для «100».

*Алгоритм проверки вторичной аутентификации

====
. Если не используется механизм авторизации OTP или проверка вторичной аутентификации отключена
.. возврат
. При вызове с аргументом `success`
.. сбросить `Максимальная ошибка вторичной аутентификации
. При вызове с аргументом `failure`
.. Увеличить счетчик «Максимальная вторичная аутентификация»
.. Если `Maximum Secondary Authentication Failures` превышает желаемое число (100)
... Постоянно блокирует пользователя
====

==== Внизу по обнаружению грубой силы {project_name}

Недостатком определения аббревиатуры {project_name} является то, что сервер становится уязвимым для атак отказа в обслуживании. При осуществлении атаки на отказ в обслуживании, злоумышленник может попытаться войти в систему, угадывая пароли для любых учетных записей, которые он знает, и в конечном итоге вынуждая {project_name} отключить аккаунты.

Рассмотреть использование программного обеспечения для предотвращения вторжений (IPS). {project_name} регистрирует каждую ошибку входа и IP адрес клиента не удалось. Вы можете указать IPS на лог файл сервера {project_name} , а IPS может модифицировать брандмауэры, чтобы блокировать соединения с этих IP адресов.
