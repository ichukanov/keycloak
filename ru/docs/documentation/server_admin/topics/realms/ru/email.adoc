= Настройка электронной почты для области

{project_name} отправляет письма пользователям для проверки их адреса электронной почты, когда они забудут свои пароли, или когда администратору необходимо получать уведомления о событии сервера. Чтобы включить {project_name} для отправки писем, вы предоставляете {project_name} настройки SMTP-сервера.

.Процедура
. Нажмите *Настройки реалма* в меню.
. Нажмите на вкладку *Email*.
+
image:images/email-tab.png[Email Tab]
. Заполните поля и переключатели по мере необходимости.

От:: *От* обозначает адрес, используемый для SMTP-заголовка для отправленных сообщений.
Из отображаемого имени:: *Из отображаемого имя* позволяет настроить дружественные псевдонимы адреса электронной почты (опционально).
Если не выбран простой *От* адрес электронной почты будет отображаться в почтовых клиентах.
Ответить:: *Ответить* означает адрес, используемый для *Ответа* SMTP-заголовка для отправленных писем (опционально).
Если не выбран простой адрес электронной почты *От*.
Ответить для отображения имени:: *Ответить на имя* позволяет настроить дружественные псевдонимы адреса электронной почты (опционально).
Если не выбран простой *Ответить на * адрес электронной почты, будет показан.
Конверт из:: *Конверт от* означает https://en.wikipedia.org/wiki/Bounce_address[Bounce Address], используемый для SMTP-заголовка отправленных сообщений (необязательно).

Хост:: *Хост* обозначает имя хоста сервера SMTP, используемого для отправки писем.
Порт:: *Порт* означает порт SMTP-сервера.
Шифрование:: Отметьте один из этих флажков для поддержки отправки писем о восстановлении имен пользователей и паролей, особенно если SMTP сервер находится во внешней сети.
Скорее всего, вам потребуется изменить *Порт* на 465, порт по умолчанию для SSL/TLS.
Проверка подлинности:: Установите этот переключатель в *ВКЛЮЧЕНИЕ*, если ваш SMTP сервер требует аутентификации.
Имя пользователя:: Все механизмы аутентификации требуют имени пользователя.
Тип аутентификации:: Выберите тип аутентификации: 'password' или 'token'.
Пароль:: Требуется только если выбран *Authentication Type* 'password'.
Передача *Пароля*.
Значение поля *Пароль* может ссылаться на значение из внешнего <_vault-administration,vault>>.
URL токена аутентификации:: Требуется только если выбран токен *Authentication Type*.
Предоставить *URL токена авторизации*, который используется для получения токена с помощью предоставленных учетных данных клиента.
Рамка токена аутентификации:: Требуется только если выбран токен *Authentication Type*.
Передача *Области Маркера Авторизации*, используемого для получения токена из *URL Маркера Автора*.
Идентификатор клиента аутентификации:: Требуется только если выбран токен *Authentication Type*.
Передайте *Идентификатор Клиента Авторизации*, который используется для получения токена из *URL Маркера Автора*.
Секрет ключа клиента:: Требуется только если выбран токен *Authentication Type*.
Передайте *Секретарь Авторизации*, который аутентифицирует клиента для получения токена из *URL-адреса токена Авторизации*.
Значение поля *Auth Client Secret* может ссылаться на значение внешнего <_vault-administration,vault>>.
Разрешить UTF-8:: Включить кодировку в UTF-8 при отправке их на сервер.
Это должно быть включено только в том случае, если почтовый сервер поддерживает UTF-8 через расширение SMTPUTF8.
Если отключено, доменные имена, содержащие неASCII символы, будут закодированы с помощью punycode, и адреса, содержащие не-ASCII символы в локальной части адреса возвращают ошибку.
+
Если реалм настроен на отправку писем (эта конфигурация SMTP настроена) и *Разрешить UTF-8* отключена, встроенный <<user-profile, user profile>> валидатор электронной почты проверяет локальную часть адреса содержит только символы ASCII. Таким образом, {project_name} предотвращает сообщения пользователей, которые не могут быть уведомлены.

== Конфигурация электронной почты XOAUTH2 с сторонними поставщиками

В следующей секции содержатся подсказки о том, как настроить настройки электронной почты {project_name} для использования аутентификации на основе XOAUTH2 с известными программными SMTP серверами сторонних разработчиков.

NOTE: Этот раздел был внесен сообществом Keycloak. Поскольку основная команда Keycloak не имеет средств для тестирования сторонних провайдеров, она предоставляется как есть. Если вы обнаружили, что эта документация устарела или неполна, пожалуйста, внесите свой вклад в ее улучшение.

=== Конфигурация для Microsoft Azure и Office365

Microsoft Azure позволяет «Предоставление учетных данных клиентам» использовать секретный ключ клиента для сбора токена доступа.
Microsoft Office365 поддерживает SMTP с XOAUTH2 для аутентификации с собранным токеном.

Ссылки на соответствующую документацию Майкрософт:

- https://learn.microsoft.com/en-us/exchange/permissions-exo/application-rbac[Использование ролевого контроля доступа для приложений в режиме онлайн обмена]
- Настройки в https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth[Аутентифицируйте IMAP, POP или SMTP с помощью OAuth]

Следующий метод настройки {project_name} для отправки электронной почты с Azure и Office365 был проверен тестом.
В зависимости от вашего окружения могут быть и другие варианты.

От:: `<some>@<domain>
Хост:: `smtp.office365.com`
Порт:: `587`
Шифрование:: Проверить TLS
Имя пользователя:: `<some>@<domain>` (может отличаться от значения отправителя)
Ссылка на токен аутентификации:: `+https://login.microsoftonline.com/<TenantID>/oauth2/v2.0/token+`
+
Замените TenantID идентификатором вашего клиента Microsoft, обычно UUID, в Azure или просто скопируйте токен url из списка конечных точек, отображаемых в консоли Azure.
Рамка токена аутентификации:: `+https://outlook.office.com/.default+`
Идентификатор клиента аутентификации:: `<ApplicationId>`
+
Замените ApplicationId идентификатором вашего приложения в Azure, обычно UUID.
Auth Token ClientSecret:: `<Secret configured>`
