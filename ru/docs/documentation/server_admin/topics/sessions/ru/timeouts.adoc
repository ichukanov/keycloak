[[_timeouts]]
=== Таймаут сессии и токенов

{project_name} включает в себя управление сессией, cookie, и токенов через вкладки *Sessions* и *Tokens* в меню *Настройки реалма*.

image:images/sessions-tab.png[Сессионная вкладка]

|===
|Конфигурация |Описание

|Закрыть SSO сеанс
|Эта настройка предназначена только для клиентов OIDC. Если пользователь не активен длиннее этого таймаута, сеанс пользователя аннулируется. Значение таймаута сбрасывается, когда клиенты запрашивают аутентификацию или посылают запрос на обновление токена. {project_name} добавляет окно времени на время простоя до того, как действие вступает в силу. См. <<_idle_timeouts_note, note>> позже в этом разделе.

|SSO сеанс Макс
|Максимальное время до окончания сеанса пользователя.

|SSO сеанс бездействие запомнить меня
|Этот параметр доступен только тогда, когда включен *Запомнить* и похож на стандартную конфигурацию SSO сеанса. Пользователи могут указывать более длинные таймауты простоя, когда они нажимают *Запомнить меня* при входе. Этот параметр является опциональной конфигурацией и если его значение не больше нуля, использует тот же тайм-аут бездействия, что и конфигурация SSO Сессии.

|Максимум запомнить меня SSO
|Этот параметр доступен только тогда, когда включен *Запомнить* и похож на стандартный SSO сеанс Макс. Пользователи могут указывать длинные сеансы, когда они нажимают *Запомнить меня* при входе в систему. Этот параметр является опциональной конфигурацией и если его значение не больше нуля, использует тот же период времени, что и конфигурация SSO Session Max .

|Идёт сеанс Клиента
|Таймаут простоя для сессии клиента. Если пользователь неактивен дольше, чем этот таймаут, то сеанс клиента аннулируется и запросы токена обновления беспокоить тайм-аут простоя. Этот параметр никогда не влияет на общую сессию пользователя SSO, которая является уникальной. Обратите внимание, что сеанс пользователя SSO является родителем 0 или более клиентских сессий, сеанс одного клиента создается для каждого приложения клиента, в котором он авторизован. Это значение должно указать короткий тайм-аут простоя, чем *SSO Session Idle*. Пользователи могут переопределить его для отдельных клиентов на вкладке "Расширенные настройки"*. Эта настройка является опциональной конфигурацией, и, когда установлено значение 0, используется тот же тайм-аут бездействия в конфигурации бездействия SSO сессии.

|Максимальный сеанс клиента
|Максимальное время сессии клиента и до истечения и недействительного ключа обновления. Как и в предыдущем варианте, этот параметр никогда не влияет на сеанс пользователя SSO и должен указывать меньшее значение, чем *SSO Session Max*. Пользователи могут переопределить его для отдельных клиентов на вкладке "Расширенные настройки"*. Эта настройка является необязательной конфигурацией, и когда установлено значение нуля, используется тот же самый максимальный тайм-аут в конфигурации SSO Session Max .

[[_offline-session-idle]]

|Простой автономный сеанс
|Эта настройка для <<_offline-access, offline access>. Время, в течение которого сеанс простаивает до того, как {project_name} отменит его токен в автономном режиме. {project_name} добавляет окно времени на время простоя до того, как действие вступает в силу. См. <<_idle_timeouts_note, note>> позже в этом разделе.

[[_offline-session-max-limited]]

|Макс. лимит автономных сессий
|Эта настройка для <<_offline-access, offline access>. Если флаг *Включен*, Offline Session Max может контролировать максимальное время сохранения токена в автономном режиме, независимо от активности пользователя. Если флаг *Выключенный*, автономные сессии никогда не истекают по времени жизни, только на простой. После активации этой опции, можно настроить <_offline-session-max, Offline Session Max>> и <<_client_offline-session-max, Client Offline Session Max>> (глобальная опция на уровне реалма).

[[_offline-session-max]]

|Максимальный автономный сеанс
|Этот параметр используется для <<_offline-access, offline access>, и это максимальное время, прежде чем {project_name} отменит соответствующий токен в автономном режиме. Эта опция контролирует максимальное количество времени, которое токен оффлайн остается активным, независимо от активности пользователя.

[[_client_offline-session-max]]

|Максимальный оффлайн сеанс клиента
|Этот параметр используется для <<_offline-access, offline access>, и это максимальное время до того, как {project_name} отменяет соответствующий токен оффлайн для клиента. Эта опция контролирует максимальное количество времени, которое токен оффлайн остается активным, независимо от активности пользователя.
Пользователи могут переопределить его для отдельных клиентов на вкладке "Расширенные настройки"*.

|Таймаут входа
|Общее время входа в систему. Если аутентификация займет больше времени, пользователь должен начать процесс аутентификации еще раз.

|Таймаут авторизации
|Максимальное количество времени, которое пользователи могут тратить на любую страницу во время процесса аутентификации.

|Пользовательские действия Lifespan
|Максимальное время до истечения права доступа пользователя. Держите это значение коротким, потому что пользователи обычно реагируют на самостоятельные действия быстро.

|Действия по умолчанию для администраторов
|Максимальное время до истечения разрешения на действие, отправленного пользователю администратором. Держите это значение длинным, чтобы администраторы могли отправлять сообщения электронной почты в оффлайн. Администратор может переопределить тайм-аут по умолчанию перед выдачей токена.

|Проверка электронной почты

|Проверка электронной почты учетной записи IdP
|Определяет независимый тайм-аут для проверки электронной почты учетной записи IdP.

|Забыли пароль
|Задает независимый тайм-аут для восстановления пароля.

|Выполнить действия
|Определяет независимый тайм-аут для выполнения действий.

[[_idle_timeouts_note]]
[NOTE]
====
Следующая логика применяется только в том случае, если постоянные сессии пользователя не активны:

Для простоя существует двухминутное окно времени, которое активно. Например, если у вас установлен тайм-аут 30 минут, то это будет 32 минуты до окончания сеанса.

Это действие необходимо для некоторых сценариев в кластерной и кросс-дата-средах, где токен обновляется на один узел кластера за короткое время до истечения срока и другие кластерные узлы неправильно считают сеанс истекшим, потому что они еще не получили сообщение об успешном обновлении с узла обновления.
====
