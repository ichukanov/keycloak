=== Проверка событий пользователя

Вы можете записывать и просматривать все события, затрагивающие пользователей. {project_name} вызывает события входа в систему для таких действий, как успешный вход пользователя, неверный пароль или обновление учетной записи пользователя. По умолчанию {project_name} не сохраняет и не отображает события в консоли администратора. Только события ошибок регистрируются в консоли администратора и в журнале сервера.

Используйте эту процедуру для начала аудита событий пользователя.

. Нажмите *Настройки реалма* в меню.
. Нажмите на вкладку *События*.
. Нажмите на вкладку *Настройки событий* пользователя.
. Включите *Сохранить события* в *ВКЛЮЧЕНИЕ*.
+
image:images/user-events-settings.png[Настройки событий]
. Укажите длину времени хранения событий в поле *Истечение*.
. Нажмите *Добавить сохраненные типы*, чтобы увидеть другие события, которые вы можете сохранить.
+
image:images/add-event-types.png[Добавить типы]
. Нажмите *Добавить*.

Нажмите *Очистить пользовательские события*, когда хотите удалить все сохраненные события.

Теперь вы можете просматривать события.

. Нажмите на вкладку *События* в меню.
+
image:images/user-events.png[Login Events]
. Чтобы отфильтровать события, нажмите *Поиск события пользователя*.
+
image:images/search-user-event.png[Поиск события пользователя]

[[event-listener]]
==== Слушатель событий

Слушатели событий прослушивают события и выполняют действия, основанные на этом событии. {project_name} включает в себя два встроенных слушателя, слушателя журнала событий и список событий по электронной почте.

===== Прослушиватель событий журнала

Когда слушатель регистрации событий включен, слушатель записывает в файл журнала при возникновении ошибки.

Пример сообщения журнала из списка событий журнала:

----
11:36:09,965 WARN  [org.keycloak.events] (default task-51) type=LOGIN_ERROR, realmId=master,
                    clientId=myapp,
                    userId=19aeb848-96fc-44f6-b0a3-59a17570d374, ipAddress=127.0.0.1,
                    error=invalid_user_credentials, auth_method=openid-connect, auth_type=code,
                    redirect_uri=http://localhost:8180/myapp,
                    code_id=b669da14-cdbb-41d0-b055-0810a0334607, username=admin
----

Вы можете использовать обработчик событий логов для защиты от атак хакеров:

. Обрабатывайте файл журнала для события `LOGIN_ERROR`.
. Извлечь IP адрес события неудачного входа.
. Отправлять IP адрес в программный инструмент предотвращения вторжений.

Прослушиватель событий логов логов журнала `org.keycloak.events`. {project_name} не включает в журнал отладки в журналах сервера, по умолчанию.

Для включения событий журнала отладки в логи сервера:

. Измените уровень журнала для категории `org.keycloak.events`
. Изменить уровень журнала, используемый слушателем журнала событий.

Чтобы изменить уровень журнала, используемый слушателем журнала событий, добавьте следующее:

[source,bash]
----
bin/kc.[sh|bat] start --spi-events-listener--jboss-logging--success-level=info --spi-events-listener--jboss-logging--error-level=error
----

Допустимыми значениями уровней логов являются `debug`, `info`, `warn`, `error` и `fatal`.

===== Прослушиватель событий

Обработчик событий Email отправляет сообщение на электронный адрес пользователя, когда произойдет событие и поддерживает следующие события:

* Ошибка входа.
* Обновить пароль.
* Обновление одноразового пароля на основе времени (TOTP).
* Удалить одноразовый пароль (OTP).
* Обновить учетные данные.
* Удалить учётную запись.

Необязательные события, которые вы можете настроить:

* Пользователь отключен по постоянной блокировке.
* Пользователь отключен по временной блокировке.

Для отправки письма необходимо выполнить следующие условия:

* У пользователя есть адрес электронной почты.
* Адрес электронной почты пользователя помечен как проверенный.

//-

.Предпосылки
* Настройки электронной почты Realm настроены.

Чтобы включить список рассылки:

. Нажмите *Настройки реалма* в меню.
. Нажмите на вкладку *События*.
. Нажмите на поле *Слушатели событий*.
. Выберите `email`.
+
image:images/event-listeners.png[listeners]

Вы можете исключить события с помощью аргумента `+--spi-events-listener--email--exclude-events+`. Например:

[source,bash]
----
kc.[sh|bat] --spi-events-listener--email--exclude-events=UPDATE_CREDENTIAL,REMOVE_CREDENTIAL
----

Чтобы включить дополнительные события, используйте следующую команду:

[source,bash]
----
kc.[sh|bat] --spi-events-listener--email--include-events=USER_DISABLED_BY_TEMPORARY_LOCKOUT_ERROR,USER_DISABLED_BY_PERMANENT_LOCKOUT
----
