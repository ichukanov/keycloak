При создании реалма аутентификационные потоки автоматически обновляются, чтобы включить определенные шаги для аутентификации участников организации и доступа к ней. Потоки аутентификации обновляются:

* *браузер*
* *первый логин брокера*

Основное изменение потока *браузер* состоит в том, что по умолчанию используется идентификатор пользователя, так чтобы пользователи были идентифицированы перед запросом их учетных данных.
Относительно первого потока входа брокера, главное изменение автоматически добавляет пользователей в качестве членов организации после того, как они аутентифицируются через поставщика идентификации, связанного с организацией и успешно завершают поток.

Выбор использования идентификатора первого логина или не зависит от существования организации в реалме.
If no organizations exist, the user follows the usual steps to authenticate using the username and password,
or any other step configured in the browser flow. В противном случае пользователю сначала требуется имя пользователя или электронная почта для продолжения аутентификации в реалме.

Главная цель - идентифицировать пользователя:

* Является ли пользователь существующим или новым пользователем?
* Является ли пользователь членом какой-либо организации в мире?
* Если участник организации, связан ли пользователь с любым идентификационным провайдером, связанным с организацией?

Depending on the outcome when identifying the user, the authentication flow changes to either proceed with authentication
by asking for the user's credentials or eventually redirect the user automatically to authenticate within the organization security
boundaries through an identity provider.

== Понимание личности первого входа

В дополнение к идентификации пользователя после ввода имени пользователя на имя пользователя также лежит ответственность за:

* Подключение домена электронной почты к организации.
* Определяет, должен ли поток аутентификации продолжать или нет, если учетная запись уже существует для указанного имени пользователя
* Принимая решение о том, как пользователь должен быть аутентифицирован в зависимости от того, как домены и поставщики идентификации настроены на организацию
и набор учетных данных, настроенных на учетную запись пользователя.
* Аутентификация пользователей через идентификационный провайдер, связанный с организацией, если домен электронной почты совпадает с доменом, установленным поставщику идентификации

The identity-first login provides the same capabilities that are provided by the usual login page with the username and
password fields. Пользователи все еще могут самостоятельно зарегистрироваться, нажав на ссылку регистрации или выбрав любой идентификатор или социальный
брокер, который не связан с организацией в этой области.

image:images/organizations-identity-first-login.png[alt="Identity-first login page"]

In the case of a user that does not exist, if that user tries to authenticate using an email domain that matches an organization domain,
the identity-first login page appears again with a message that the username provided is not valid.
На данный момент нет необходимости запрашивать у пользователя учетные данные.

image:images/organizations-identity-first-error.png[alt="Ошибка входа в систему"]

Существует несколько опций для регистрации пользователя, позволяющего пользователю аутентифицироваться в области и присоединиться к организации.

Если в области включена настройка саморегистрации, пользователь может нажать на ссылку *Зарегистрироваться* на первой странице входа в систему
и создать учетную запись в реалме.
После этого администратор может отправить пригласительную ссылку пользователю или вручную добавить пользователя в состав организации.
Подробнее см. <<_managing_members_,Managing members>>.

Если у организации есть идентификатор провайдера без домена и настройка *Скрыть на странице входа в систему* *OFF*, пользователи также могут щелкнуть по ссылке
поставщика идентификации на странице идентификации для автоматического создания учетной записи и присоединения к организации
после аутентификации через поставщика идентификационных данных.
Подробнее см. <<_managing_identity_provider_,Managing identity providers>.

В аналогичной ситуации с предыдущим разделом организации может быть установлен провайдер идентификации с одним из доменов организации.
В этой ситуации пользователь перенаправляется на провайдера идентификации, если электронная почта этого пользователя соответствует определенному домену организации.
По завершению процесса создается учетная запись и пользователь присоединяется к организации. In case the user has any first-factor credentials
configured (e.g.: password, passwordless, kerberos) to the account, the user is not automatically redirected to the identity provider but asked to authenticate using their
credentials.

== Настройка существующих потоков аутентификации

Как уже упоминалось выше, потоки аутентификации автоматически обновляются с необходимыми шагами
для поддержки организаций и аутентификации их участников. For existing realms, in addition to enabling organizations to the
realm, you also need to manually update your existing (custom) authenticating flows.

Измените поток *браузера*, выполнив следующие шаги:

.Процедура
. Дублировать текущий поток, связанный с типом привязки *Browser flow*, во избежание разрыва потока, который вы используете
. Нажмите *Добавить подпоток* и присвойте ему имя *Моя Организация*
. Переместите новый подпоток *Моя Организация* для выполнения сразу после шага запуска *Identity Provider Redirector*.
The main point here is that the sub-flow should happen before any other sub-flow or execution step that authenticates the
user using whatever credentials you support in your realm. После добавления измените *Требования* на *Альтернатива*.
. Нажмите *Добавить подпоток* в подпотоке *Моя Организация* и введите его имя, например, *Моя организация - Условия*. После добавления измените *Требования* на *Условие*.
. Нажмите *Добавить условие* в подпотоке *Моя организация - Условие* и выберите *Условие - настроенный пользователь*. После добавления измените *Требования* на *Обязательные*.
. Нажмите *Добавить шаг* в подпотоке *Моя организация - Условия* и выберите *Организация Идентификатор Первого Входа
* шаг выполнения. После добавления измените *Требования* на *Альтернатива*.
. Привязка потока аутентификации к типу привязки *браузер*.

image:images/organizations-browser-flow.png[alt="Браузер организаций"]

После включения параметра <_enabling_organization_,Organizations>> в область и создания
по крайней мере одной организации, вы можете видеть страницу идентификации и начать использовать организации
в своем реалме.

Измените *первый логин брокера*, следуя следующим шагам:

.Процедура
. Дублируйте текущий поток, связанный с *первым брокером входного потока*, чтобы избежать разрыва потока, который вы используете
. Нажмите *Добавить подпоток* и введите его имя, например, `Член организации - Условие`. После добавления измените *Требования* на *Условие*.
. Нажмите *Добавить условие* в подпотоке *Член организации - Условие* и выберите *Условие - настроенный пользователь*. После добавления измените *Требования* на *Обязательные*.
. Щелкните *Добавить шаг* в суб-потоке *Член Организации - Условие* и выберите шаг выполнения *Член Организации*. После добавления измените *Требования* на *Обязательные*.
. Привязка потока аутентификации к привязке *First broker login*.

image:images/organizations-first-broker-flow.png[alt="Первые брокерские потоки организаций"]

Теперь вы должны иметь возможность аутентифицироваться с помощью любого поставщика идентификации, связанного с организацией
и зарегистрироваться пользователем, присоединившимся к организации в качестве участника, как только он завершит первый поток входа в браузер.

== Настройка аутентификации пользователей

Если поток поддерживает организации, вы можете настроить некоторые шаги для изменения аутентификации пользователей в реалме.

Например, некоторые варианты использования требуют от пользователей аутентификации в Realm только в том случае, если они являются членами какой-либо организации или конкретной организации в реалме.

Чтобы включить это поведение, вам нужно включить опцию «Требует членства пользователя» на шаге выполнения «Идентификатор организации - первый вход», нажав на его настройки.

If enabled, and after the user provides the username or email in the identity-first login page, the server will
try to resolve a organization where the user is a member by looking at any existing membership or based on the semantics of the <<_mapping_organization_claims_,organization>> scope,
if requested by the client. Если не является членом организации, будет показана страница с ошибкой.
