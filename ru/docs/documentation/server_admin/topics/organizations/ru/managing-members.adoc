[[_managing_members_]]
= Управление участниками

Член организации является пользователем области с ссылкой на одну или несколько организаций. They are logically separated
from other users in a realm so that you know exactly which users belong to an organization.

Есть различные способы добавить члена организации или совета директоров в организацию:

* Добавление существующего пользователя в реалм как участника
* Через идентификационный провайдер, связанный с организацией
* Отправка приглашения для создания новой учетной записи
* Отправка приглашения существующему пользователю присоединиться к организации

Один член организации, Учетная запись этого пользователя может управляться так же, как и любой обычный аккаунт в реалме, зайдя в раздел *Пользователи* в меню.

Однако при управлении организацией вы можете сужать пользователей только теми пользователями, которые связаны с этой организацией. На этой вкладке у вас есть список всех членов организации и действий для добавления новых членов и редактирования и удаления существующих членов.

image:images/organizations-manage-members.png[alt="Управление участниками организации"]

Вы также можете управлять членством пользователя в организации из раздела *Пользователи*. Когда вы выбираете пользователя, вы можете увидеть список организаций, к которым принадлежит пользователь, и управлять этими членами.

image:images/organizations-users-section.png[alt="Управление членами организации из раздела "]

== Управляемые и неуправляемые участники

При управлении членами, учитывайте, как их отношения с организацией влияют на жизненный цикл их счетов.
Участники могут присоединиться к организации через различные потоки, и каждый поток указывает на силу связи между своими счетами и организацией.

Существует два типа участников:

* *Управляется*
* *Неуправляемый*

Управляемые члены - это участники, управляемые организацией, и они не могут существовать за пределами своей организации. Например, рассмотрите
учетную запись, созданную через идентификационный провайдер, связанный с организацией. Этот счет не принадлежит к сфере, которая была объединена в организацию.
In this case, the single source of truth for the identity is the organization and its lifecycle is controlled
by the organization.
Если вы удалите организацию или участника, аккаунт также удаляется из реалма.

С другой стороны, неуправляемые члены являются членами, которые могут существовать без организации. For instance, when adding an existing
realm user to an organization, the account belongs to the realm first and foremost and eventually linked to an organization. В этом случае
удаление организации или участника не приведет к удалению учетной записи из реалма; миром является
единственным источником истины за самобытность.

== Добавление существующего пользователя в реалм как участника

Существующий пользователь области может присоединиться к организации, выбрав этого пользователя из списка и добавив пользователя в организацию.

.Процедура
. Нажмите *Добавить участника*.
. Нажмите *Добавить пользователя Realm*.
. Выберите одного или нескольких пользователей и нажмите *Добавить*, чтобы добавить их в организацию.

image:images/organizations-add-realm-user.png[alt="Добавление пользователя реалма"]

После того, как пользователь является членом организации, этот пользователь может аутентифицироваться в реалме так же, как и обычный пользователь и использовать
любые учетные данные, поддерживаемые реалмом.

== Приглашение пользователей

Администратор может отправлять по электронной почте пользователей для вступления в организацию.

.Процедура
. Нажмите *Добавить участника*.
. Нажмите *Пригласить участника*.
. Укажите адрес электронной почты
. Нажмите *Отправить*

image:images/organizations-invite-member.png[alt="Приглашение членов"]

По желанию, вы также можете ввести значение поля *Имя* и *Фамилия* для более персонального сообщения электронной почты
используя приветствие с именем и фамилией получателя письма.

Приглашение - это по существу письмо, отправленное со ссылкой, на которую человек должен нажать для выполнения необходимых шагов для присоединения к
организации. These steps depend on whether the person already has an account in the realm or if a new account should
be created before joining the organization.

If the email maps to an existing user in a realm, the steps the user will follow are basically about confirming the
intention to join the organization.

С другой стороны, если ни один пользователь не связан с данным адресом электронной почты, шаги
будут включать создание новой учетной записи с помощью саморегистрации. In this case, the user is forced
to provide the same email address used to send the invitation.

== Управление приглашениями

{project_name} provides comprehensive invitation management capabilities that allow administrators to track, manage, and control
organization invitations throughout their lifecycle.

=== Просмотр приглашений

Смотреть и управлять всеми приглашениями для организации:

.Процедура
. Выберите организацию, которой вы хотите управлять.
. Нажмите на вкладку *Приглашения*.

В списке приглашений отображаются все отправленные приглашения со следующей информацией:

* *Email* - Адрес электронной почты приглашенного пользователя
* *Статус* - Текущий статус приглашения (Отложение, Истекло)
* *Создано* - Когда приглашение было отправлено
* *Истекает срок действия приглашения (если это применимо)

Вы можете фильтровать приглашения по статусу, чтобы легко найти ожидающие или просроченные приглашения.

=== Управление приглашением на жизненный цикл

Администраторы могут выполнять различные действия по приглашениям:

==== Повторно отправленные приглашения

Для повторной отправки приглашения:

.Процедура
. Из списка приглашений найдите приглашение, которое вы хотите повторить.
. Нажмите на меню действий рядом с приглашением.
. Выберите *Отправить*.

Новое письмо с приглашением будет отправлено получателю с истечением срока действия.

==== Удаление приглашений

Чтобы удалить запись приглашения навсегда:

.Процедура
. Из списка приглашений найдите приглашение, которое вы хотите удалить.
. Нажмите на меню действий рядом с приглашением.
. Выберите *Удалить*.
. Подтвердите удаление.

Это окончательно удаляет приглашение из системы. Это действие нельзя отменить.

=== Состояние приглашений и жизненный цикл

Приглашения проходят через несколько состояний в течение их жизни:

* *В ожидании* - приглашение было отправлено и ожидает подтверждения получателем
* *Истекло* - Время окончания действия приглашения истекло

NOTE: Когда пользователь успешно принимает приглашение, приглашение автоматически удаляется из системы.

=== Доступ к API

Приглашения организации также можно управлять программно через API администратора REST API:

* `GET /admin/realms/{realm}/orgs/{orgId}/invitations` - Список всех приглашений
* `GET /admin/realms/{realm}/orgs/{orgId}/invitations/{invitationId}` - Получить специальное приглашение
* `POST /admin/realms/{realm}/orgs/{orgId}/invitations/{invitationId}/resend` - Отправить приглашение повторно
* `УДАЛИТЬ /admin/realms/{realm}/orgs/{orgId}/invitations/{invitationId}` - Удалить приглашение

Подробную документацию по API см. в документации {project_name} администратора REST API.

== Участники-пользователи с помощью идентификатора провайдера

Организация может иметь своего собственного самоидентификационного провайдера в качестве единого источника истины для своей самобытности. In this case,
users federated from the identity provider are automatically added as a member of the organization.

When users join an organization through an identity provider associated with an organization, they are automatically marked
as managed members. В этом случае они будут проходить через логин брокера, настроенные в области и присоединяться к организации
автоматически, как только они успешно аутентифицируются.

Onboarding new members through an identity provider can be done by either automatically redirecting the user to an organization's
identity provider or by selecting the identity provider when at the login page.

В обоих случаях, когда пользователь предоставит письмо, {project_name} будет пытаться сопоставить организацию на основе домена электронной почты. В случае, если
домена электронной почты соответствует организации, и идентификационный провайдер связан с одним и тем же доменом и настройка *перенаправление при совпадении домена электронной почты*
, пользователь автоматически перенаправляется на поставщика идентификационных данных. Once the user authenticates at the identity provider
and completes the first broker login flow, the user is automatically added as an organization member.

On the other hand, if *Redirect when email domain matches* is not enabled, but the identity provider is configured not to
*Hide on login page*, the user can select the identity provider and then be redirected to the identity provider to continue
the onboarding process.

Подробнее см. <<_managing_identity_provider_,Managing Identity Providers>.

== Удаление участника

Вы можете удалить участника из организации.

В меню действий рядом с членом вы хотите удалить, нажмите *Удалить*.

When removing a member from an organization, remember that the user may or may not be removed from a realm depending on if
that user is managed or unmanaged member, respectively.

Подробнее см. <<_managed_unmanaged_members_,Managed and unmanaged members>.

== Просмотр членства в группах организации

Вы можете посмотреть какие группы организации принадлежит участнику непосредственно из контекстного меню участника.

.Процедура
. Для просмотра членства в группах из вкладки *Члены*:
.. Перейдите в вашу организацию.
.. Нажмите на вкладку *Участники*.
.. Найдите участника.
.. Нажмите на меню kebab (<unk> ) рядом с участником.
.. Выберите *Показать членство в группах организаций*.
. Для просмотра членства в группе из конкретной группы:
.. Перейдите в вашу организацию.
.. Нажмите на вкладку *Группы*.
.. Выберите группу.
.. Нажмите на вкладку *Участники*.
.. Найдите участника.
.. Нажмите на меню kebab (<unk> ) рядом с участником.
.. Выберите *Показать членство*.
. Для просмотра членства в группах с подробной страницы пользователя:
.. Нажмите *Пользователи* в меню.
.. Выберите пользователя.
.. Нажмите на вкладку *Организации*.
.. Найдите организацию.
.. Нажмите на меню kebab (<unk> ) рядом с организацией.
.. Выберите *Показать членство в группах организаций*.

Отображает все группы из конкретной организации, к которым в настоящее время назначен участник.

== Поддержка федеративных членов

Пользователи, пришедшие от федеративных провайдеров, также могут быть добавлены в качестве членов организации. Исключениями являются пользователи провайдеров LDAP с отключенным режимом *импорта*. Члены организации добавляются во внутреннюю группу, которая не синхронизирована с внешними провайдерами, , даже если провайдер LDAP имеет сопоставление групп с режимом LDAP_ONLY, для неимпортированных пользователей будет невозможно добавить как членов организации, так как такое членство не будет синхронизироваться с сервером LDAP.

Другими словами, LDAP пользователи, которые не импортированы не могут присоединиться к организации, так как членство не хранится в локальной базе данных или на сервере LDAP. Таким образом, если вы хотите, чтобы пользователи LDAP присоединились к организациям, убедитесь, что режим импорта LDAP провайдера включен.
