= Понимание концов SCIM

Все конечные точки SCIM используют тип содержимого `application/scim+json` для запросов и ответов, как указано в RFC 7644.
Тип содержимого `application/json` также принимается для запросов.

== Доступные конечные точки

В следующей таблице резюмируются все имеющиеся конечные точки SCIM:

[cols="2,1,3", options="header"]
|===
|Endpoint
|Методы
|Описание

|`/Пользователи`
|ПОЛУЧИТЬ
|Список всех пользователей или создать нового пользователя.

|`/Пользователи/{id}`
|GET, PUT, PATCH, УДАЛИТЬ
|Получь, заменить, частично обновить или удалить конкретного пользователя.

|`/Пользователи/.search`
|ПОСТ
|Поиск пользователей с телом запроса (полезно для сложных или длинных выражений).

|`/группы`
|ПОЛУЧИТЬ
|Список всех групп или создать новую группу.

|`/Группы/{id}`
|GET, PUT, PATCH, УДАЛИТЬ
|Получь, заменить, частично обновить или удалить конкретную группу.

|`/Группыs/.search`
|ПОСТ
|Поиск групп с использованием тела запроса.

|`/ServiceProviderConfig`
|ПОЛУЧИТЬ
|Получить возможности SCIM, поддерживаемые сервером.

|`/Виды ресурсов`
|ПОЛУЧИТЬ
|Список типов ресурсов (Пользователь, Группа), доступных на сервере.

|`/Schemas`
|ПОЛУЧИТЬ
|Список всех схем SCIM, поддерживаемых сервером, включая расширения.
|===

== Методы HTTP

SCIM API поддерживает следующие методы HTTP для управления ресурсами:

[cols="1,1,2", options="header"]
|===
|Метод
|Код статуса
|Описание

|ПОСТ
|201 Создано
|Создать новый ресурс.

|ПОЛУЧИТЬ
|200 ОК
|Получить один ресурс по ID, или список/поиск.

|ПОКУПИТЬ
|200 ОК
|Заменить существующий ресурс целиком.

|ПАТЧ
|200 ОК
|Частично изменяйте ресурс, используя операции добавления, замены или удаления.

|УДАЛИТЬ
|204 Нет контента
|Удалить ресурс.
|===

== Параметры запроса

Следующие параметры запроса могут быть использованы с GET запросами для управления ответом. The same parameters
are also accepted in the body of `POST /.search` requests.

[cols="1,1,3", options="header"]
|===
|Параметр
|Тип
|Описание

|`фильтр`
|Строка
|Выражение фильтра SCIM для поиска ресурсов. См. <<_scim_filtering_resources,Filtering resources>>.

|`startIndex`
|Целое
|1 ориентированный индекс первого результата возврата. По умолчанию 1.

|`count`
|Целое
|Максимальное количество результатов для возврата на странице.

|`attributes`
|Строка
|Список имён атрибутов, разделённых запятыми, для включения в ответ. Если указано, то включаются только перечисленные атрибуты (плюс `id` и `schemas`, которые всегда возвращаются).

|`excludedAttributes`
|Строка
|Список имён атрибутов, разделенных запятыми, для исключения из ответа. Применяется после фильтра `attributes`. Атрибут `id` не может быть исключен.

|`sortBy`
|Строка
|Имя атрибута для сортировки по результату. См. примечание ниже.

|`sortOrder`
|Строка
|Порядок сортировки: «по возрастанию» (по-умолчанию) или «по убыванию». См. примечание ниже.
|===

NOTE: While the `sortBy` and `sortOrder` parameters are accepted by the API, custom sorting is not currently
supported. Resources are returned in the default order used by the underlying store, consistent with the
behavior of the {project_name} Admin REST API.

== Метаданные ресурса

Каждый SCIM ресурс, возвращаемый API, включает в себя объект `meta` со следующими атрибутами:

[cols="1,3", options="header"]
|===
|Атрибут
|Описание

|`resourceType`
|Тип ресурса (например, `User` или `Group`).

|`создан`
|Временная метка при создании ресурса в формате ISO 8601.

|`lastModified`
|Временная метка при последней модификации ресурса в формате ISO 8601.

|`размещение`
|Полный URI ресурса (например, `\http://localhost:8080/realms/myrealm/scim/v2/Users/{id}`).
|===
