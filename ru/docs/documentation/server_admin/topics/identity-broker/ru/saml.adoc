=== Идентификатор SAML v2.0

{project_name} может использовать идентификационные провайдеры на основе протокола SAML v2.0.

.Процедура
. Нажмите на *Identity Providers* в меню.
. Из списка `Добавить провайдера` выберите `SAML v2.0`.
+
image:images/saml-add-identity-provider.png[Добавить Identity Provider]
. Введите начальные параметры конфигурации. Смотрите <<_general-idp-config, General IDP Configuration>> для получения дополнительной информации о параметрах конфигурации.


.Конфигурация SAML
|===
|Конфигурация |Описание

|ID сущности поставщика услуг
|SAML Entity ID, который удаленный поставщик удостоверений использует для идентификации запросов от этого поставщика услуг. По умолчанию этот параметр установлен в базовом URL миров `<root>{kc_realms_path}/{realm-name}`.

|ID сущности провайдера идентификации
|ID сущности, используемый для проверки эмитента принятых утверждений SAML. Если пусто, проверка эмитента не производится.

|URL службы Single Sign-On
|SAML конечная точка, которая начинает процесс аутентификации.  Если ваш SAML IDP публикует дескриптор сущностей IDP, то здесь указывается значение этого поля.

|URL службы артефактов
|Артефактное разрешение SAML. Если ваш SAML IDP публикует дескриптор сущностей IDP, то здесь указывается значение этого поля.

|URL-адрес службы разового выхода
|The SAML выход конечной точки. Если ваш SAML IDP публикует дескриптор сущностей IDP, то здесь указывается значение этого поля.

|Выход из бэк-канала
|Включите этот переключатель в *ВКЛЮЧЕНИЕ*, если ваш SAML IDP поддерживает выход из канала.

|Формат имяID политики
|Ссылка URI, соответствующая формату идентификатора имени. По умолчанию {project_name} устанавливает его в `urn:oasis:names:tc:SAML:2.0:nameid-format:persistent`.

|Тип участника
|Определяет, какая часть SAML будет использоваться для идентификации и отслеживания внешних идентификаторов пользователей. Может быть либо Subject NameID, либо SAML атрибут (либо по имени, либо по понятному имени). Значение поля NameID предмета не может быть задано вместе с значением 'urn:oasis:names:tc:SAML:2.0:nameid-format:transient' Формат Политики Названий.

|Основные атрибуты
|Если основной тип не пустой, то в этом поле указывается имя ("Атрибут [Name]") или дружественное имя ("Атрибут [Дружественное Имя]") идентифицирующего атрибута.

|Разрешить создание
|Разрешить внешнему поставщику идентификации создать новый идентификатор для представления принципала.

|Ответ привязки HTTP-POST
|Управляет привязкой SAML в ответ на любые SAML запросы, посылаемые внешним IDP. Когда *OFF*, {project_name} использует привязку к перенаправлению.

|Ответ привязки ARTIFACT
|Управляет привязкой SAML в ответ на любые SAML запросы, посылаемые внешним IDP. Когда *OFF*, {project_name} оценивает конфигурацию Binding Response HTTP-POST.

|HTTP-POST привязка для AuthnRequest
|Управляет привязкой SAML при запросе аутентификации от внешнего IDP. Когда *OFF*, {project_name} использует привязку к перенаправлению.

|Нужна подписка по авторам
|При *ВКЛЮЧЕНИи*, {project_name} использует клавиши миры для подписи запросов, посланных внешнему SAML IDP.

|Нужна подпись
|Указывает, ожидает ли поставщик этой услуги подписанного Assertion.

|Нужны зашифрованные
|Указывает, ожидает ли поставщик этой услуги зашифрованного Assertion.

|Алгоритм подписи
|*Хотите подписать Автор* *ВКЛЮЧЕН* алгоритм подписи. Обратите внимание, что алгоритмы `SHA1` устарели и могут быть удалены в будущих версиях.
Мы рекомендуем использовать более безопасный алгоритм вместо `*_SHA1`. Также, с алгоритмами `*_SHA1`, Проверка подписей
не работает, если провайдер идентификации SAML (например, другой экземпляр {project_name}) работает на Java 17 или выше.

|Алгоритм шифрования
|Алгоритм шифрования, используемый SAML IDP для шифрования документов SAML
, утверждений или ID. Соответствующий ключ дешифрования
для расшифровки документов SAML будет выбран на основе этого настроенного алгоритма, и
должен быть доступен в ключах Realm для использования в шифровании (ENC). If the
algorithm is not configured, any supported algorithm is allowed and a
decryption key will be chosen based on the algorithm specified in SAML document
itself.

|Название ключа подписи SAML
|Подписанные документы SAML, отправленные с помощью привязки POST, содержат идентификацию ключа подписи в элементе `KeyName`, который, по умолчанию, содержит ID ключа {project_name}. Внешние SAML IDP могут ожидать другое имя ключа. Этот переключатель определяет, содержит ли `KeyName`:
* `KEY_ID` - ID ключа.
* `CERT_SUBJECT` - предмет из сертификата, соответствующего ключу реалма. Microsoft Active Directory Federation Services ожидает `CERT_SUBJECT`.
* `NONE` - {project_name} опущает подсказку к имени ключа из SAML сообщения.

|Принудительная аутентификация
|Пользователь должен ввести свои учётные данные во внешнем IDP, даже если пользователь уже вошёл в систему.

|Проверка подписи
|Когда *ВКЛЮЧЕНИЕ*, миры ожидают, что запросы SAML и ответы внешних ВПЛ будут подписаны в цифровом виде.

|URL дескриптора метаданных
|Внешний URL-адрес, где Identity Provider публикует метаданные `IDPSSODescriptor`. Этот URL используется для загрузки сертификатов поставщика удостоверений личности, когда нажаты клавиши `Перезагрузить` или `Импорт ключей`.

|Использовать URL дескриптора метаданных
|При *ВКЛЮЧЕНИи*, сертификаты для проверки подписей автоматически загружаются из `URL дескриптора метаданных` и кэшируются в {project_name}. Провайдер SAML может проверять подписи двумя разными способами. Если запрашивается конкретный сертификат (обычно в привязке 'POST'), а не в кэше, сертификаты автоматически обновляются с URL. Если всем сертификатам предлагается проверить подпись (привязку `REDIRECT`), обновление выполняется только после максимального времени кэша. Максимальное время может быть указано в самом дескрипторе, атрибутах `cacheDuration` или `validUntil`, или в качестве провайдера кэширования определяется. Смотрите https://www.keycloak.org/server/all-provider-config[public-key-storage] spi во всех конфигурациях провайдера для получения дополнительной информации о том, как работает кэш. TTL кэша по умолчанию для метаданных SAML составляет 24 часа (86,400 секунд).

Когда опция *OFF*, для проверки подписей используются сертификаты `Validating X509 Certificates`.

|Проверка сертификатов X509
|Публичные сертификаты {project_name} используют для проверки подписей запросов SAML и ответов внешнего IDP, когда `Use metadata descriptor URL` *OFF*. Несколько сертификатов могут быть введены запятыми (`,`). Сертификаты могут быть повторно импортированы из URL-адреса дескриптора метаданных, нажав на действие «Импорт ключей» на странице поставщика идентификации. Действие загружает текущие сертификаты в конечной точке метаданных и назначает их в конфигурацию в том же самом варианте. Вам нужно нажать «Сохранить», чтобы определённо сохранить повторно импортированные сертификаты.

|Подписать метаданные поставщика услуг
|Когда *ON*, {project_name} использует пару ключей миры для подписи <_identity_broker_saml_sp_descriptor, метаданных провайдера SAML Service Provider>>.

|Пройти тему
|Контролирует если {project_name} передает IDP параметр запроса `login_hint`. {project_name} добавляет значение этого поля в параметр login_hint в теме AuthnRequest'а, чтобы поставщики назначения могли предварительно заполнить форму входа.

|Индекс потребительских характеристик
|Определяет набор атрибутов для запроса удаленного IDP. {project_name} автоматически добавляет атрибуты, сопоставленные в конфигурации поставщика идентификации к автогенерируемому документу метаданных SP.

|Имя сервиса, использующего атрибуты
|Описательное имя для набора атрибутов, которое рекламируется в автогенерируемом документе SP метаданных.
|===

Вы можете импортировать все данные конфигурации, указав URL или файл, указывающий на SAML IDP дескриптор внешней IDP. Если вы подключаетесь к {project_name} внешнему IDP, вы можете импортировать настройки IDP из URL-адреса `<root>{kc_realms_path}/{realm-name}/protocol/saml/descriptor`. Эта ссылка представляет собой XML-документ, описывающий метаданные о IDP. Вы также можете импортировать все эти данные конфигурации, указав URL или XML-файл, указывающий на внешний SAML IDP дескриптор сущностей для подключения.

[[_identity_broker_saml_requested_authncontext]]
==== Запрос конкретных контекстов AuthnContexts

Поставщики удостоверений личности помогают клиентам указать ограничения на метод проверки личности пользователя. Например, запрос об аутентификации MFA, Kerberos или требований безопасности. Эти ограничения используют конкретные критерии AuthnContext. Клиент может запросить один или несколько критериев и указать, как поставщик удостоверений должен соответствовать запрошенному AuthnContext, точно, или выполнив другие эквиваленты.

Вы можете перечислить критерии, которые требуется предоставить поставщику услуг путем добавления ClassRefs или DeclRefs в разделе Запрошенные AuthnContext Constraints . Обычно вам нужно предоставить ClassRefs или DeclRefs, поэтому посмотрите документацию вашего поставщика удостоверений личности, какие значения поддерживаются. Если ClassRefs или DeclRefs не присутствует, то поставщик удостоверений не вводит дополнительных ограничений.


.Ограничения запрашиваемых AuthnContext
|===
|Конфигурация |Описание

|Сравнение
|Метод идентификации провайдера использует для оценки контекстных требований. Доступные значения: `Exact`, `Minimum`, `Maximum`, или `Better`. Значение по умолчанию: `Exact`.

|AuthnContext ClassRefs
|AuthnContext ClassRefs описывает требуемые критерии.

|AuthnContext DeclRefs
|AuthnContext DeclRefs, описывающий требуемые критерии.
|===

[[_identity_broker_saml_sp_descriptor]]
==== Дескриптор SP

Когда вы получите доступ к метаданным SAML SP, найдите элемент `Endpoints` в настройках провайдера идентификации. Он содержит ссылку `SAML 2.0 Service Provider Metadata` , которая генерирует дескриптор сущности SAML для поставщика услуг. Вы можете скачать дескриптор или скопировать его URL и импортировать его в удаленный провайдер идентификации.

Эти метаданные также доступны публично, перейдя по следующей ссылке:

[source,subs=+attributes]
----
http[s]://{host:port}{kc_realms_path}/{realm-name}/broker/{broker-alias}/endpoint/descriptor
----

Убедитесь, что вы сохранили изменения конфигурации перед доступом к дескриптору.

[[_identity_broker_saml_login_hint]]
==== Отправить тему в SAML запросах

По умолчанию, социальная кнопка, указывающая на SAML Identity Provider перенаправляет пользователя на следующий логин URL:

[source,subs=+attributes]
----
http[s]://{host:port}{kc_realms_path}/${realm-name}/broker/{broker-alias}/login
----

Добавление параметра запроса с именем `login_hint` в этот URL добавляет значение параметра в SAML запрос в качестве атрибута Subject . Если этот параметр запроса пуст, то {project_name} не добавляет объект запроса.

Включите опцию "Pass subject" для отправки темы в SAML запросах.
