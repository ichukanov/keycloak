=== Обзор брокеров

При использовании {project_name} в качестве идентификационного брокера {project_name} не заставляет пользователей предоставлять свои учетные данные для аутентификации в определенном реале. {project_name} отображает список идентификационных провайдеров, из которых они могут аутентифицироваться.

Если вы настраиваете поставщика идентификации по умолчанию, {project_name} перенаправляет пользователей на поставщика по умолчанию.

[NOTE]
====
Различные протоколы могут потребовать различных потоков аутентификации. Все поставщики идентификации поддерживаемые {project_name} используют следующий поток.
====

image:images/identity_broker_flow.png[Идентификационный поток брокера]

. Неавторизованный пользователь запрашивает защищённый ресурс в клиентском приложении.
. Приложение клиента перенаправляет пользователя на {project_name} на аутентификацию.
. {project_name} отображает страницу входа со списком провайдеров идентификации, настроенных в реалме.
. Пользователь выбирает одного из идентификационных провайдеров, нажав на кнопку или ссылку.
. {project_name} выдаёт запрос на аутентификацию целевому поставщику идентификации, запрашивающему аутентификацию и перенаправляет пользователя на страницу входа поставщика идентификации. Администратор уже установил параметры подключения и другие параметры конфигурации для поставщика идентификации консоли администратора.
. Пользователь предоставляет учетные данные или дает согласие на аутентификацию поставщика идентификационных данных.
. После успешной проверки подлинности провайдером пользователь перенаправляет обратно на {project_name} с ответом аутентификации. Обычно ответ содержит токен безопасности, используемый {project_name} для доверия к аутентификации идентификатора поставщика и получения информации о пользователе.
. {project_name} проверяет правильность ответа от поставщика идентификации.
Если это верно, {project_name} импортирует и создает пользователя, если он еще не существует. {project_name} может попросить поставщика идентификации предоставить дополнительную информацию о пользователе, если токен не содержит этой информации. Это поведение является федерацией _идентичности_.
Если пользователь уже существует, {project_name} может попросить пользователя привязать идентификатор, возвращаемый поставщиком идентификации с существующей учетной записью. Это поведение - привязка _аккаунта_. С {project_name}вы можете настроить _привязку аккаунта_ и указать его в <_identity_broker_first_login,First Login Flow>>. На этом шаге {project_name} аутентифицирует пользователя и выдает его токен для доступа к запрошенному ресурсу в поставщике услуг.
. При аутентификации пользователя, {project_name} перенаправляет пользователя на провайдера сервиса, отправив токен, ранее выданный во время локальной аутентификации.
. Провайдер услуг получает токен от {project_name} и разрешает доступ к защищенному ресурсу.

Возможны вариации этого потока. Например, клиентское приложение может запросить определенного поставщика идентификации вместо отображения списка или вы можете установить {project_name} для принудительного предоставления дополнительной информации перед объединением их личности.

В конце процесса аутентификации {project_name} выпускает свой токен клиентским приложениям. Клиентские приложения отличаются от внешних идентификаторов, поэтому они не могут видеть протокол клиентского приложения или проверить личность пользователя. Провайдеру нужно знать только об {project_name}.
