=== Основная конфигурация

Основой индивидуальной конфигурации брокеров являются идентификационные провайдеры (IDP). {project_name} создает идентификационные данные для каждого реалма и разрешает им по умолчанию для каждого приложения. Пользователи из Realm могут использовать любой из зарегистрированных провайдеров идентификации при входе в приложение.

.Процедура
. Нажмите на *Identity Providers* в меню.
+
image:images/identity-providers.png[Identity Providers]
. Выберите поставщика идентификации. {project_name} отображает страницу конфигурации для выбранного поставщика идентификации.
+
image:images/add-identity-provider.png[Добавить Facebook Identity Provider]
+
При настройке поставщика идентификации, поставщик идентификации появляется на странице входа в систему {project_name}. Вы можете размещать пользовательские иконки на экране входа в систему для каждого поставщика удостоверений. См. https://www.keycloak.org/ui-customization/themes#custom-identity-providers-icons[custom icons] для получения дополнительной информации.
+
image:images/identity-provider-login-page.png[]
Соцсети:: Социальные провайдеры поддерживают социальную аутентификацию в вашем мире. С {project_name}пользователи могут войти в ваше приложение, используя учетную запись социальной сети. Поддерживаемые провайдеры включают Twitter, Facebook, Google, LinkedIn, Instagram, Microsoft, PayPal, Openshift v4, GitHub, GitLab, Bitbucket, и Stack Overflow.
Протокол:: Протоколные провайдеры полагаются на конкретные протоколы для аутентификации и авторизации пользователей. Используя этих провайдеров, вы можете подключиться к любому поставщику идентификации, соответствующему определенному протоколу. {project_name} поддерживает протоколы SAML v2.0 и OpenID Connect v1.0. Вы можете настроить и брокер любого поставщика удостоверений личности на основе этих открытых стандартов.

Хотя каждый тип идентификационного провайдера имеет свои настройки конфигурации, все они имеют общую конфигурацию. Доступны следующие параметры конфигурации:

.Общая конфигурация
[cols="1,1", options="header"]
|===
|Конфигурация
|Описание

|Alias
|Псевдоним является уникальным идентификатором поставщика идентификации и ссылается на внутреннего поставщика идентификационных данных. {project_name} использует алиас для построения редиректов URI для протоколов OpenID Connect, которым требуется редиректный URI или обратный URL для связи с провайдером идентификации. Все поставщики удостоверений личности должны иметь псевдоним. Примеры псевдонимов включают `facebook`, `google` и `idp.acme.com`.

|Включено
|Включает/выключает провайдера.

|Скрыть на странице входа
|При *ВКЛЮЧЕНИи*, {project_name} не отображает этого провайдера в качестве параметра входа на странице входа. Клиенты могут запрашивать этого провайдера с помощью параметра 'kc_idp_hint' в URL для запроса логина.

|Только привязка аккаунта
|Когда *ВКЛЮЧЕНИЕ*, {project_name} привязывает существующие учетные записи к этому провайдеру. Этот провайдер не может войти в систему пользователей, и {project_name} не отображает этого провайдера в качестве опции на странице входа в систему.

|Маркеры магазина
|Когда *ON*, {project_name} хранит токены от поставщика идентификации.

|Хранимые токены доступны для чтения
|При *ВКЛЮЧЕНИи* пользователи могут получить идентификационный код поставщика. Это действие также применимо к _брокер_ клиентской роли _read token_.

|Доверять Email
|Когда *ВКЛЮЧЕНИЕ*, {project_name} доверяет адреса электронной почты от поставщика удостоверений. Если реалм требует проверки электронной почты, то пользователям, которые войдут в систему с этой идентификацией, не нужно выполнять верификацию по электронной почте.
Если целевой идентификатор провайдера поддерживает верификацию электронной почты и рекламирует эту информацию при возврате информации профиля пользователя, email федеративного пользователя будет снят как проверенный.
Например, поставщик подключения OpenID возвращает претензию `email_verified` в своих идентификационных токенах.
Обратите внимание, что эта настройка установит электронную почту проверенной, когда пользователь впервые и при последующих входе в систему
через брокера, если для режима синхронизации установлен `FORCE`.

|Порядок интерфейса
|Порядок сортировки доступных идентификаторов поставщиков на странице входа.

|Подтвердить существенные претензии
|Когда *ВКЛЮЧЕНИЕ*, идентификационные токены, выданные поставщиком идентификации, должны иметь конкретную претензию, в противном случае пользователь не может аутентифицироваться через этого брокера

|Существенные претензии
|Если *Подтвердить существенную претензию* *ВКЛЮЧЕНИЕ*, то имя токена JWT для фильтрации (совпадение чувствительно к регистру)

|Существенная стоимость владения
|Когда *Проверьте наличие существенной претензии* *ВКЛЮЧЕН*, значение токена JWT для совпадения (поддерживает формат регулярных выражений)

|Первый вход в систему
|Процесс аутентификации {project_name} включает, когда пользователи впервые используют этого поставщика идентификации для входа в {project_name}.

|Пост Вход в Поток
|Процесс аутентификации {project_name} запускается, когда пользователь заканчивает вход с внешним идентификатором провайдера.

|Режим синхронизации
|Стратегия обновления информации пользователя от поставщика данных через картографов. При выборе *legacy*, {project_name} использовал текущее поведение. *Импорт* не обновляет пользовательские данные и *принуди* обновляет пользовательские данные, когда это возможно. Смотрите <<_mappers, Identity Provider Mappers>> для получения дополнительной информации.

|Имя пользователя с учетом регистра
|Если включено, то исходное имя пользователя от поставщика идентификации хранится как при федерации пользователей. В противном случае имя пользователя поставщика идентификации имеет нижний регистр и может не совпадать с исходным значением, если оно чувствительно к регистру. Эта настройка влияет только на имя пользователя, связанное с федеративным именем пользователя на сервере, всегда в нижнем регистре.

|Показать в консоли аккаунта
|Определяет, как поставщик идентификации будет доступен в консоли аккаунта. Если установлено значение `Всегда`, он всегда доступен.
Если установлено значение `When linked`, оно будет отображаться только когда пользователь связан с ним. В противном случае, если установлено значение `Никогда`, он не будет доступен, даже если пользователь связан с ним.
|===
