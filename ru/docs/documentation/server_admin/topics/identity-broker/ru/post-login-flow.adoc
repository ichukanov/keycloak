[[_identity_broker_post_login_flow]]
=== Пост потока входа

Почтовый поток входа полезен для ситуаций, когда вы хотите вызвать некоторые дополнительные действия проверки подлинности после каждого входа с конкретным поставщиком идентификатора.
Например, вы можете вызвать двухфакторную аутентификацию после каждого входа {project_name} в `Facebook`, потому что `Facebook` не предоставляет двухфакторную аутентификацию во время его входа.

После того, как вы настроили процесс аутентификации с необходимыми шагами, установите его как `Post login flow` при настройке поставщика идентификации.

==== Примеры пост-потока

===== Запрос двухфакторной аутентификации после входа провайдера идентификации

Простейший способ обеспечить аутентификацию одним конкретным двухфакторным методом. Например, при запросе OTP, поток может выглядеть как это имеет только один настроенный аутентификатор.
Этот тип потока требует от пользователя настроить OTP во время первого входа с идентификатором, предоставляя, когда у пользователя нет OTP установлен в учетной записи.

image:images/post-login-flow-otp.png[Post login OTP]

Более сложная настройка может включать несколько методов двухфакторной аутентификации, настроенных как `ALTERNATIVE`. In this case, make sure that the user is requested to setup one of
the methods if that user does not yet have any 2-factor authentication configured on the account. Это можно было бы сделать следующим образом:

* Убедитесь, что один из двухфакторных методов настроен как `REQUIRED` в <_identity_broker_first_login, First login flow>. Этот метод может работать, если вы ожидаете, что все ваши пользователи будут зарегистрированы
авторизацией провайдера.
* Перенесите двухфакторные методы как «ALTERNATIVE» в условный подпоток, такой как один метод под названием «2FA» и создайте другой условный подпоток типа «OTP, если нет 2FA»,
который будет срабатывать только если предыдущий подпоток не был выполнен и попросит пользователя добавить один из двухфакторных методов (например, OTP). Пример подобной конфигурации потока представлен
в секции <_conditional-2fa-otp-default, Conditions главы Authentication flows chapter>>.

==== Запрос дополнительных шагов аутентификации для выделенных клиентов

В некоторых случаях клиенту или группе клиентов может потребоваться выполнить некоторые дополнительные шаги после входа в провайдер.
Ниже приведен пример потока, который предписывает, что при запросе клиентской области «foo», пользователь должен авторизоваться с помощью OTP после входа поставщика идентификации.

image:images/post-login-flow-client-scope.png[Войти после входа в систему с клиентом и OTP]

Это пример настройки `Condition - client scope` для запроса указанной клиентской области.

image:images/post-login-flow-client-scope-config.png[Конфигурация потока входа клиента пост]

The requested clients need to have this client scope set on them either
as default or as optional. В последнем случае поток выполняется только в том случае, если клиентская область запрашивается (например, по параметру `scope` в случае входа клиента OIDC/OAuth2).
