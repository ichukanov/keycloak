==== OpenShift 4

.Предпосылки
. Сертификат экземпляра OpenShift 4, хранимый в Truststore {project_name}.
. Сервер {project_name} настроен для использования магазина доверия. Для получения дополнительной информации смотрите https://www.keycloak.org/server/keycloak-truststore[Configuring a Truststore] {section}.

//-

.Процедура
. Найдите API-адрес экземпляра Openshift 4, используя эту команду:
+
[source,bash,subs=+attributes]
----
oc cluster-info
----
. Ищите URL в строке, которая имеет этот формат:
+
[source,bash,subs=+attributes]
----
Kubernetes master is running at https://api.<your-openshift-domain>:6443
----
. В консоли администратора выберите в меню *Identity Providers*.
. Из списка *Добавить провайдера* выберите *Openshift v4*.
. Введите *Client ID* и *Client Secret* и в поле *Base URL*, введите API URL вашего экземпляра OpenShift 4. Кроме того, вы можете скопировать *Redirect URI* в буфер обмена.
+
image:images/openshift-4-add-identity-provider.png[Добавить идентификатор]
. Зарегистрируйте своего клиента либо через консоль OpenShift 4 (Главная -> API Explorer -> OAuth Client -> Instances) или с помощью инструмента `oc` командной строки.
+
[source, subs="attributes+"]
----
$ oc create -f <(echo '
kind: OAuthClient
apiVersion: oauth.openshift.io/v1
metadata:
 name: kc-client <1>
secret: "..." <2>
redirectURIs:
 - "<here you can paste the Redirect URI that you copied in the previous step>" <3>
grantMethod: prompt <4>
')
----

//-
<1> `name` вашего клиента OAuth. Передано как параметр запроса `client_id` при выполнении запросов к `_<openshift_master>_/oauth/authorize` и `_<openshift_master>_/oauth/token`. Параметр `name` должен совпадать с параметром `OAuthClient` и конфигурацией {project_name}.
<2> `secret` {project_name} использует в качестве параметра запроса `client_secret`.
<3> Параметр `redirect_uri` указанный в запросах к `_<openshift_master>_/oauth/authorize` и `_<openshift_master>_/oauth/token` должен быть равен (или предустановлен) одному из URI в `redirectURI`. Самый простой способ его правильно настроить - скопировать его из страницы конфигурации {project_name} OpenShift 4 Identity Provider (поле `Redirect URI`).
<4> `grantMethod` {project_name} использует для определения действия, когда этот клиент запрашивает токены, но пользователь не получил доступ к ним.

В конце вы увидите OpenShift 4 Identity Provider на странице входа вашего экземпляра {project_name}. После нажатия вы должны быть перенаправлены на страницу входа OpenShift 4.

image:images/openshift-4-result.png[Result]
