[[_oidc_token_role_mappings]]
= Сопоставления ролей в токене

Когда пользователь аутентифицируется, существуют некоторые роли, которые добавляются в маркер доступа. By default, the <<proc-creating-realm-roles_{context},Realm roles>> are added to the access
token into the `realm_access` claim. <<con-client-roles_{context},Client roles>> добавлены по умолчанию в претензию `resource_access`.

Добавленные в токен роли являются пересечением:

* Роли <_oidc_token_role_mappings_user_roles,назначенные пользователя>.
* <<_role_scope_mappings,Соответствия области ролей>> ролей разрешённых клиенту для доступа

[[_oidc_token_role_mappings_user_roles]]
== Роли, назначенные пользователю

Роли, назначенные пользователю, могут быть определены в сопоставлениях ролей, как описано в <<proc-assigning-role-mappings_{context},this section>>. Несколько подробностей:

* В случае, если пользователь является членом некоторых <<proc-managing-groups_{context},groups>>, то также применяются все роли этих групп.
* В случае, если роль представляет собой <_composite-roles,composite role>, то также применяются дочерние роли составной роли. В токене список ролей расширяется и будет содержать все роли.
* В случае, если аутентифицированный пользователь не является обычным пользователем, а <_service_accounts, ervice account>>, который представляет клиента, затем используются роли учетной записи службы. The service account roles are defined
in the tab *Service account roles* of the particular client.

== Сопоставители протоколов ролей

Подобно другим требованиям, роли добавляются в токен доступа, выданный клиенту выделенным <_protocol-mappers,Protocol mappers>>. Существует <<_client_scopes_protocol,Встроенный охват клиента *roles*>>
определен в этом реалме. Так как это <<proc_updating_client_scopes_{context},Realm default client scope>>, по умолчанию он определяется как <<_client_scopes_linking,По умолчанию scope>> для каждого клиента Realm.
Эта область действия клиента вы можете увидеть в консоли администратора, просматривая вкладку *Клиентские границы* и затем ищущая *роли* область видимости. Эта область действия клиента содержит данные карты протоколов по умолчанию:

* *Realm mapper *mapper* - Этот протокол сопоставляет роли области в фиксации фиксации. По умолчанию, конфигурация выглядит так:

image:images/mapper-oidc-realm-roles.png[]

* Сопоставление протокола *роли клиентов* - Этот протокол сопоставляется, используется для добавления роли клиента в требование токена. По умолчанию, конфигурация выглядит так:

image:images/mapper-oidc-client-roles.png[]

* *Отображаемая аудитория* - Этот картоппер протокола используется для заполнения претензии «aud» в токене доступа на основе заявленных ролей клиентов. Подробности об этом mapper находятся в <<_audience_resolve,Разрешение аудитории>>.

Как вы можете видеть в конфигурации ролей и карт ролей клиентов, можно настроить:

* Если роли добавляются только в токен доступа или в другие токены, например ID токен. По умолчанию, роли добавляются к токену доступа и к конечной точке самоопределения.
* Каковы претензии, где будут добавляться роли. По умолчанию, роли области добавляются в утверждение `realm_access`. Так, например, претензия в токене JWT, содержащем 2 роли в области `role1` и `role2` будет выглядеть примерно так:
+
[source,json]
----
"realm_access": {
  "roles": [ "role1", "role2" ]
}
----
+
По умолчанию в претензию токена `resource_access` добавляются роли клиента. Это утверждение будет выглядеть как это в токене, которая содержит
роли клиента `manage-account` и `manage-account-links` клиента `account` и роли клиента `target-client1-role` клиента `target-client1`:
+
[source,json]
----
"resource_access": {
  "target-client1": {
    "roles": [ "target-client1-role" ]
  },
  "account": {
    "roles": [ "manage-account", "manage-account-links" ]
  }
}
----

При настройке конфигурации *Имя претензии* токенов* рольщиков протокола роли, можно указать, что эти роли будут добавлены в токен в сконфигурированной претензии.

Если вы хотите обновить роль требует только одного конкретного клиента (например, клиент `foo` ожидает роли области в претензии `realm-realm-roles` вместо претензии `realm_access`), тогда
можно удалить стандартный диапазон клиентов *ролей* из вашего клиента и вместо этого настроить сопоставление протокола Realm/client в <<_client_scopes_dedicated, Выделенный клиентский охват>> вашего клиента.
