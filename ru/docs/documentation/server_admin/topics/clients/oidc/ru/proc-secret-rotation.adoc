= Создание политики секретной ротации клиента OIDC

Ниже приводится пример определения политики секретного ротации:

.Процедура
. Нажмите *Настройки реалма* в меню.
. Нажмите вкладку *Клиентские Политики*.
. На странице *Profiles* щелкните *Создать профиль клиента*.
+
image:images/create-oidc-client-profile.png[Создать профиль клиента]
. Введите любое имя для *Имя*.
. Введите описание, которое поможет идентифицировать цель профиля для *Описания*.
. Нажмите *Сохранить*.
+
Это действие создает профиль и позволяет настроить исполнителей.
. Нажмите *Добавить исполнитель* для настройки исполнителя для этого профиля.
+
image:images/create-oidc-client-secret-rotation-executor.png[Профиль клиента Executor]
. Выберите _secret-rotation_ для *Executor Type*.
. Введите максимальную длительность каждого секрета в секундах для *секретной завершения*.
. Введите максимальную длительность каждого повернутого секрета в секундах для *Повернутого секрета*.
+
WARNING: Помните, что значение *Повернутой Секретной Истека* должно быть меньше, чем *Срок Секрета*.
. Введите количество времени, в секундах, после которого любое действие обновления обновит клиент на *Осталось времени просрочки*.
. Нажмите *Добавить*.
+
====
В приведенном выше примере:

* Каждый секрет действителен на одну неделю.
* Поворачиваемый секрет истекает через два дня.
* Окно обновления динамических клиентов запускается за день до истечения секрета.
====
. Вернуться на вкладку *Клиентские Политики*.
. Нажмите *Политики*.
. Нажмите *Создать политику клиента*.
+
image:images/create-oidc-client-secret-rotation-policy.png[Политика ротации клиентов]
. Введите любое имя для *Имя*.
. Введите описание, которое поможет вам определить цель политики *Описания*.
. Нажмите *Сохранить*.
+
Это действие создает политику и позволяет ассоциировать политику с профилями. Это также позволяет настроить условия для выполнения политики.
. В соответствии с Условиями нажмите *Добавить условие*.
+
image:images/create-oidc-client-secret-rotation-condition.png[Условия политики ротации клиентов]
. Для применения поведения ко всем конфиденциальным клиентам выберите _client-access-type_ в поле *Condition Type*
+
[NOTE]
====
Чтобы применить к определенной группе клиентов, другой подход будет состоять в выборе типа _client-roles_ в поле *Condition Type*. Таким образом, вы можете создать определенные роли и назначить индивидуальную конфигурацию вращения для каждой роли.
====
. Добавьте _конфиденциальность_ в поле *Тип доступа для клиентов*.
. Нажмите *Добавить*.
. Вернуться к настройкам политики в _Client Profiles_, нажмите *Добавить клиент* и выберите *Еженедельный профиль ротации клиента* из списка и нажмите *Добавить*.
+
image:images/oidc-client-secret-rotation-policy.png[Политика ротации клиентов]

[NOTE]
====
Чтобы применить режим секретного ротации к существующему клиенту, выполните следующие действия:

.Использование консоли администратора
. Нажмите *Клиент* в меню.
. Нажмите на клиента.
. Нажмите на вкладку *Учетные данные*.
. Нажмите *Перегенерировать* секретной информации клиента.
====

---

.С помощью REST сервисов клиента можно выполнять двумя способами:
* Через операцию обновления клиента
* Через регенерацию терминала клиента
