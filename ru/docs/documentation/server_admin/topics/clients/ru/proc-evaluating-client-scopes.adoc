Вкладка *Mappers* содержит карты протоколов, а вкладка *Область* содержит сопоставления ролевых рамок, объявленных для этого клиента. Они не содержат картографов и сопоставлений рамок, унаследованных от границ клиента. Можно видеть эффективные карты протокола (т.е. карты протокола, определенные на самом клиенте, а также унаследованные от связанных границ клиента) и эффективные сопоставления рамок ролей, используемых при создании токена для клиента.

.Процедура
. Нажмите на вкладку *Клиент* для клиента.
. Откройте подвкладку *Оценить*.
. Выберите дополнительные рамки клиента, которые вы хотите применить.

Также будет показано значение параметра *scope*. This parameter needs to be sent from the application to the {project_name} OpenID Connect authorization endpoint.

[NOTE]
====
Если ваше приложение использует {securing_apps_base_link}/javascript-adapter[{project_name} JavaScript adapter], смотрите его раздел, чтобы узнать, как отправить *scope* параметр с желаемым значением.
====

Вы также можете смоделировать как маркер доступа, ID токен, или UserInfo ответ, выданный этому клиенту, ищет выбранного пользователя и специфическое значение параметра `audience`. Note
that the `audience` parameter is currently only supported for the token exchange grant. Рекомендуется оставлять пустым при имитации любой другой субсидии.

image:images/client-scopes-evaluate.png[]

Все примеры генерируются для конкретного пользователя и выдаются для конкретного клиента, с указанным значением параметра *scope*. Примеры включают все претензии и сопоставления ролей.
