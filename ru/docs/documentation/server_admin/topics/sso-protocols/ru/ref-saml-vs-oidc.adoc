=== OpenID Connect по сравнению с SAML

[role="_abstract"]
В нижеследующем перечне перечислены некоторые факторы, которые необходимо учитывать при выборе протокола.

Для большинства целей {project_name} рекомендует использовать OIDC.

*OIDC*

* OIDC специально разработан для работы с сетью.
* OIDC подходит для HTML5/JavaScript-приложений, так как на стороне клиента проще реализовать, чем SAML.
* OIDC токены находятся в формате JSON, что облегчает использование Javascript.
* OIDC имеет возможности, чтобы упростить реализацию безопасности. Например, см. ссылку:https://openid.net/specs/openid-connect-session-1_0.html#ChangeNotification[iframe trick], что спецификация определяет статус входа пользователя.

*SAML*

* SAML разработан как слой работы поверх веба.
* SAML может быть более подробным, чем OIDC.
* Пользователи выбирают SAML над OIDC, потому что есть представление о том, что это зрелое.
* Пользователи выбирают SAML над OIDC существующими приложениями, которые защищены им.
