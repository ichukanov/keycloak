==== Одноразовые пароли, основанные на времени или встречные

Алгоритмы {project_name} для ваших генераторов OTP основываются на времени и контрбазируются.

С помощью одноразового пароля, основанного на времени (TOTP), генератор токенов хэширует текущее время и общий секрет.  Сервер проверяет OTP, сравнивая хэши в пределах окна времени с представленным значением.  Точки действительны в течение короткого окна времени.

С помощью одноразовых паролей (HOTP), {project_name} использует общий счетчик, а не текущее время. Сервер {project_name} увеличивает счетчик с каждым успешным OTP входом. Действующие OTP изменения после успешного входа.

TOTP является более безопасным, чем HOTP, так как соответствующий OTP действителен на короткое окно времени, в то время как OTP для HOTP действителен на неопределенное количество времени. Удобство HOTP больше, чем TOTP, потому что не существует временного лимита для входа в OTP.

Для HOTP требуется обновление базы данных каждый раз, когда сервер увеличивает счетчик. Это обновление - потеря производительности сервера аутентификации при большой нагрузке. Для повышения эффективности TOTP не запоминает используемые пароли, поэтому нет необходимости в обновлении базы данных. Недостаток заключается в том, что можно повторно использовать TOTP в действительном интервале времени.

==== Параметры конфигурации TOTP

===== Алгоритм хэша OTP

Алгоритм по умолчанию - SHA1. Другими вариантами защиты являются SHA256 и SHA512.

===== Количество цифр

Длина ОТП.  Короткие OTP удобны, проще печатать и запоминать. Более длинные OTP более безопасны, чем более короткие OTP.

===== Осмотреть окно

Количество интервалов, которое сервер пытается сопоставить с хэшами. Эта опция присутствует в {project_name} , если часы генератора TOTP или сервера аутентификации устарели. Значение 1 по умолчанию является адекватным. Например, если временной интервал для токена составляет 30 секунд, значение 1 означает, что он примет правильные токены в 90-секундном окне (интервал времени 30 секунд + взгляд впереди 30 секунд + взгляд за 30 секунд). Каждое увеличение этого значения увеличивает допустимое окно на 60 секунд (перед 30 секунд + смотрится 30 секунд).

===== Период токена OTP

Временной интервал в секундах, когда сервер совпадает с хэшем. Каждый раз, когда интервал передается, генератор токена генерирует TOTP.

===== Повторное использование кода

Определяет, могут ли OTP токены повторно использоваться в процессе аутентификации или пользователь должен ждать следующего токена.
Пользователи не могут повторно использовать эти токены по умолчанию, и администратору необходимо явно указать, что эти токены могут быть повторно использованы.

==== Параметры конфигурации HOTP

===== Алгоритм хэша OTP

Алгоритм по умолчанию - SHA1. Другими вариантами защиты являются SHA256 и SHA512.

===== Количество цифр

Длина ОТП.  Короткие OTP удобны, проще печатать и запоминать. Более длинные OTP более безопасны, чем более короткие OTP.

===== Осмотреть окно

Количество предыдущих и последующие интервалы, которые сервер пытается сопоставить с хэшами. Эта опция присутствует в {project_name} , если часы генератора TOTP или сервера аутентификации устарели. Значение 1 по умолчанию является адекватным. Эта опция присутствует в {project_name} , чтобы посмотреть, когда счетчик пользователей становится опережающим сервером.
