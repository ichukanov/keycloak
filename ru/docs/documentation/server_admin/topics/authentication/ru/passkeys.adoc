[id="passkeys_{context}"]
=== Пароли

{project_name} поддерживает https://fidoalliance.org/passkeys/[Passkeys]. {project_name} работает как паролей, полагающихся на (RP).

Регистрация и аутентификация паролем выполняются с использованием тех же возможностей xref:webauthn_{context}[WebAuthn]. *Passkeys* относятся к xref:_webauthn_loginless[LoginLess WebAuthn], поскольку они пытаются избежать любого пароля при входе в систему.
Поэтому пользователи {project_name} могут осуществлять регистрацию и аутентификацию Passkey с помощью существующих xref:webauthn_{context}[регистрации и аутентификации WebAuthn], используя *passwordless* варианты.

Функция *Passkeys* легко интегрируется в формы аутентификации по умолчанию двумя разными способами. При включении, оба условного интерфейса и модального интерфейса доступны в формах, в которых отображаются вводные данные пользователя (например, *Форма пароля пользователя* или *Форма имени пользователя*).
Точное поведение при загрузке страницы — будет ли диалог выбора пароля автоматически появляться или же учетные данные доступны только через автозаполнение браузера — контролируется параметром *Передача паролей* в политике *WebAuthn Passwordless Policy*.

Кроме того, формы паролей, когда имя пользователя уже было выбрано, всегда показывать модальную кнопку пользовательского интерфейса для входа по паролю, если текущий пользователь имеет связанные учетные данные WebAuthn. Таким способом модальный и условный интерфейс может быть использован для выполнения полного входа с нуля, который требует имя пользователя и пароль, и только modal UI отображается, когда имя пользователя уже выбрано в процессе аутентификации (из-за повторной проверки подлинности или потому, что пользователь был выбран ранее в процессе не использования секретного ключа).

*Паролей* были добавлены в следующие реализации аутентификатора:

. *Форма для пароля пользователя *: Форма для имени пользователя и пароля, используемая по умолчанию в {project_name}.
. *Форма имени пользователя*: Форма, в которой имя пользователя отображается отдельно и обычно сопровождается формой пароля. Этот аутентификатор используется, когда поля имени пользователя и пароля должны быть представлены пользователю в два различных шага.
. *Форма пароля*: Аутентификация с помощью *Passkeys* в *Форме имени пользователя* пропускает следующее выполнение *Форма пароля*. *Форма пароля* проверяет подлинность пользователя с использованием учетных данных WebAuthn без паролей, и если это так, пароль не запрашивается. Если *Форма паролей* не может быть пропущен, то она позволяет использовать modal UI для аутентификации пользователя, если учетная запись имеет привязанные учетные данные пароля.
. *Organization Identity - First Login*: Форма организации, используемая при включенной опции <_enabling_organization_, organizations>> для этой области включена. Использование *Passkeys* на этом этапе позволяет избежать последующего исполнения формы имени пользователя и пароля таким же образом, как и в форме имени пользователя.
. *Форма для имени пользователя для повторной аутентификации провайдера*: похожа на стандартный *Форму для пароля пользователя*, но используется в первом потоке входа для повторной аутентификации и подтверждения права собственности на учетную запись. Теперь доступна кнопка modal UI для повторной аутентификации.

Наконец, поток *browser* по умолчанию изменяется, чтобы пропустить поток *Browser - Conditional 2FA*, если ключ был использован ранее для аутентификации аккаунта. Так что теперь, когда пароли включены в Realm, 2FA предоставляется только в том случае, если пользователь ввел общий пароль для входа, а не в случае использования пароля. Новый *Состояние - учетные данные* добавляется в подпоток для проверки представленных ранее учетных данных. Если вы хотите всегда использовать 2FA, вы можете просто изменить требование с *Обязательно* на *Отключено* для этого условия. См. <<conditions-in-conditional-flows, Conditions in conditional flows>> для получения дополнительной информации.

[NOTE]
====
Как синхронизированные пароли, так и привязанные к устройству Passkeys могут использоваться как для аутентификации Same-Device так и для Cross-Device Authentication (CDA).
Тем не менее, работа с паролем зависит от окружения пользователя. Убедитесь, какие операции могут быть успешными в https://passkeys.dev/device-support/[environment].
====

[[_passkeys-conditional-ui]]
==== Аутентификация Passkey с использованием условного пользовательского интерфейса или автозаполнения

Условный пользовательский интерфейс (UI) или автозаполнение — это функция, связанная с паролем, в которой вводится имя пользователя (поле, в котором введено имя пользователя) помечен маркером автозаполнения `webauthn` (например, с использованием атрибута `autocomplete="username webauthn"`). Когда пользователь нажимает в такое поле ввода, пользовательский агент (браузер) может отобразить список обнаруженных учетных данных, из которых пользователь выбирает, и, возможно, дайте пользователю возможность _попробовать другой способ_. Если пользователь выбирает один из предоставленных паролей, {project_name} инициализирует аутентификацию WebAuthn этим ключом и избегает любых типов паролей.

По сравнению с xref:_webauthn_loginless[LoginLess WebAuthn], аутентификация улучшает пользовательский опыт аутентификации.

image:images/passkey-conditional-ui-autofill.png[Passkey Authentication with Conditional UI Autofill using Chrome browser]

[NOTE]
====
Эта аутентификация использует https://github.com/w3c/webauthn/wiki/Explainer:-WebAuthn-Conditional-UI/[WebAuthn Conditional UI].
Поэтому успех аутентификации зависит от среды пользователя.
Если среда не поддерживает WebAuthn Conditional UI, то пользователь должен использовать прямой модальный интерфейс или имя пользователя и пароль входа.
====

==== Аутентификация паролей с помощью модального интерфейса

Тем не менее, поскольку условный интерфейс иногда не может показывать пользователю все учетные данные, модальный интерфейс всегда может быть запущен с помощью кнопки *Войдите с помощью Passkey*. Интерфейс модального пользователя (UI) гарантирует, что все пароли будут использоваться, включая те, которые хранятся в аппаратных токенах или на других устройствах, которые не могут быть перечислены без пользовательского взаимодействия.

Кнопка modal UI также отображается в формах пароля при уже выбранном пользователе, Например, при повторной аутентификации в общем *Форме пароля пользователя*. В этом случае модальный интерфейс ограничен учетными данными WebAuthn, которые {project_name} определена для учетной записи.

image:images/passkey-modal-ui.png[Passkey Authentication with Modal UI using Chrome browser]

[[_passkeys-mediation]]
==== Посредник паролем

Параметр *Медиация паролей* в политике безпарольного доступа WebAuthn* определяет, как браузер взаимодействует с паролями пользователя при загрузке страницы входа в систему. It maps directly to the https://developer.mozilla.org/en-US/docs/Web/API/CredentialsContainer/get#mediation[`mediation` параметра WebAuthn `navigator.credentials.get()` API].

.Параметры медиации паролем
[cols="1,3", options="header"]
|===
|Значение
|Поведение

|«условие» (по умолчанию)
|При загрузке страницы диалоговое окно не отображается. Пароли доступны только через раскрывающийся список автозаполнения браузера при фокусировании поля ввода имени пользователя. Это наименее назойливый параметр и соответствует поведению <_passkeys-conditional-ui,Conditional UI>>. Если браузер не поддерживает условное медиа-соединение, то поведение равно «нет».

|«нет»
|При загрузке страницы автоматическое действие passkey не выполняется. Пользователь все еще может аутентифицироваться с помощью секретного ключа, нажав на кнопку *Войти с помощью Passkey*. Используйте этот параметр, если вы хотите, чтобы пароли были доступны, но не должны показывать никаких запросов автоматически.

|`опционное`
|При загрузке страницы автоматически отображается диалог выбора паролей. Браузер может пропустить запрос, если учетные данные не найдены. Используйте это, чтобы пригласить пользователя использовать секретный ключ без его строгого применения.

|«требуется»
|При загрузке страницы сразу же отображается диалог выбора паролей. Пользователь вынужден аутентифицировать или вручную отклонить запрос, чтобы продолжить. Используйте это, когда проверка пароля является обязательным требованием для текущего действия.

|«тихий»
|Браузер пытается аутентифицироваться без какого-либо взаимодействия пользователя или видимого интерфейса. Аутентификация не удается, если требуется взаимодействие пользователя. Это предназначено для продвинутых сценариев и вряд ли увенчается успехом для большинства типов паролей.
|===

[NOTE]
====
Поведение параметра `mediation`, хотя и определено в спецификации, может варьироваться в зависимости от браузеров и аутентификаторов. {project_name} просто передает эту опцию во время процесса регистрации. Фактическое окончательное поведение выходит за рамки его контроля. Например, поддержка `required` и `silent` медиации известны как разные между браузерами. Обратитесь к документации вашего браузера, прежде чем полагаться на эти значения в производстве.

Если в политике *Прикрепления для аутентификации* установлено значение `platform`, а в устройстве отсутствует аутентификатор, подтверждающий пользователь, автоматический поток паролей при загрузке страницы пропущен, независимо от значения медиации. Пользователь по-прежнему может аутентифицироваться, используя кнопку *Войти с помощью Пароля* или вернуться к авторизации с паролем.
====

==== Настройка

Настройте аутентификацию Passkey для форм по умолчанию:

. (Если еще не создан) Проверьте необходимое действие для *Регистрация WebAuthn без пароля* включено. Используйте шаги, описанные в <<_webauthn-register, Enable WebAuthn Authenticator Registration>>, но используйте *WebAuthn Register Passwordless* вместо *WebAuthn Register*.
. Настройте *WebAuthn безпарольную политику* таким же образом, что и в xref:_webauthn_loginless[LoginLess WebAuthn]. Конфигурация по умолчанию для безпарольной политики обычно достаточно для корректной интеграции паролей.
. В консоли администратора перейдите на вкладку *Параметры реалма* → *Авторизация*. В разделе *Настройка экрана входа в систему* активируйте *Включение переключателя паролей*. Используйте значок настроек рядом с переключателем, чтобы перейти к *политике безпарольного доступа* для дополнительной конфигурации.
. После включения *Включите Passkeys*, появляются *Передача паролей*. Выберите значение, которое лучше всего подходит вашему варианту использования. По умолчанию значение `conditional` сохраняет незаметное поведение — passkeys предлагаются только через автозаполнение. Переключитесь на `optional`, если вы хотите, чтобы браузер автоматически открывал диалог выбора ключей при загрузке страницы, позволяя пользователю удалять его и вернуться на autofill. Смотрите <<_passkeys-mediation,Mediation>> для описания всех доступных значений.
+
NOTE: Емкость хранилища обычно ограничена аппаратными ключами доступа, что означает, что вы не можете хранить много видимых учетных данных в вашем коде. Однако это ограничение может быть смягчено, например, если вы используете Android-телефон с поддержкой учетной записи Google в качестве устройства с паролем или iPhone, поддерживаемого Bitwarden.
