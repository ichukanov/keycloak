=== Политики паролей

При создании {project_name} мира он не связывает политики паролей с миром. Вы можете установить простой пароль без ограничений по его длине, безопасности или сложности. Простые пароли недопустимы в среде производства. {project_name} имеет набор политик паролей, доступных через консоль администратора.

.Процедура
. Нажмите *Authentication* в меню.
. Нажмите на вкладку *Политики*.
. Выберите политику для добавления в раскрывающемся списке *Добавить политику*.
. Введите значение, применимое к выбранной политике.
. Нажмите *Сохранить*.
+
image:images/password-policy.png[Политика паролей]

После сохранения политики {project_name} вводит политику для новых пользователей.

[NOTE]
====
Новая политика не будет эффективной для существующих пользователей. Таким образом, убедитесь, что вы устанавливаете политику паролей с начала создания реалма или добавляете «Обновить пароль» к существующим пользователям или используйте «Срок действия пароля», чтобы убедиться, что пользователи обновили свои пароли в ближайшие «N» дни, , который действительно будет настроен на новые политики паролей.
====

==== Типы политики паролей

===== ХэшАлгоритм

Пароли не хранятся в чёрном тексте. Перед хранением или проверкой {project_name} хэши используют стандартные алгоритмы хэширования.

Поддерживаемые алгоритмы хеширования паролей отображаются в следующей таблице.

[%autowidth, cols="m,"]
|===
|Алгоритм хэширования |Описание

|аргон2
|Argon2 (по умолчанию для не-FIPS развертываний)

|pbkdf2-sha512
|PBKDF2 с SHA512 (по умолчанию для развертывания FIPS)

|pbkdf2-sha256
|PBKDF2 с SHA256

|pbkdf2
|PBKDF2 с SHA1 (устарело)
|===

It is highly recommended to use Argon2 when possible as it has significantly less CPU requirements compared to PBKDF2, while
at the same time being more secure.

Алгоритм хеширования паролей по умолчанию для сервера можно настроить с помощью `+--spi-password-hashing--provider-default=<algorithm>+`.

Чтобы предотвратить чрезмерное использование памяти и ЦП, параллельные вычисления хэшей Argon2 по умолчанию ограничены количеством ядер, доступных JVM.
Чтобы настроить провайдер хэширования Argon2, используйте его параметры провайдера.

См. ссылку:{developerguide_link}[{developerguide_name}] о том, как добавить свой алгоритм хэширования.

[NOTE]
====
Если вы измените алгоритм хэширования, хэши паролей в хранилище не будут меняться до тех пор, пока пользователь не войдет.
====

===== Итерации хэширования

Количество определяет пароли {project_name} перед хранением или проверкой. Значение по умолчанию - -1,
, которое использует по умолчанию хеширование итераций для выбранного алгоритма хэширования, как указано в следующей таблице.

[%autowidth, cols="m,>"]
|===
|Алгоритм хэширования |Итерации хэша по умолчанию

|аргон2
|5

|pbkdf2-sha512
|210,000

|pbkdf2-sha256
|600,000

|pbkdf2
|1,300,000
|===

[NOTE]
====
В большинстве случаев итерации хэширования не следует менять на рекомендованные значения по умолчанию. Меньшие значения для итераций
не обеспечивают достаточной безопасности, в то время как более высокие значения приводят к более высоким требованиям к мощности процессора.
====

===== Digits

Количество цифровых цифр, необходимых в строке пароля.

===== Строчные символы

Количество строчных букв в строке пароля.

===== Символы верхнего регистра

Количество заглавных букв в строке пароля.

===== Специальные символы

Количество специальных символов в строке пароля.

===== Не имя пользователя

Пароль не может совпадать с именем пользователя.

===== Не email

Пароль не может совпадать с адресом электронной почты пользователя.

===== Регулярное выражение

Пароль должен совпадать с одним или несколькими регулярными выражениями Java.
См. https://docs.oracle.com/ru/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html[Документация Java] для регулярных выражений.

===== Срок действия пароля

Количество дней, в течение которых пароль является допустимым. По истечении срока действия пароля пользователь должен изменить свой пароль.

===== Не недавно использовано

Пароль не может быть использован пользователем. {project_name} хранит историю используемых паролей. Количество сохраненных старых паролей настраивается в {project_name}.

===== Не используется (в днях)

Пароль не может быть повторно использован в указанный период времени (в днях).
Если новый пароль был последний раз установлен в течение этого периода, пользователь будет вынужден предоставить другой пароль.

===== Черный список паролей

Пароль не должен быть в черном списке.

* Blacklist - это UTF-8 обычные текстовые файлы с Unix концами. Каждая строка представляет собой пароль из черного списка.
* {project_name} сравнивает пароли без учета регистра.
* Значение файла в черном списке должно быть именем файла в черном списке, например, `100k_passwords.txt`.
* Исправлена ошибка в `+${kc.home.dir}/data/password-blacklists/+` по умолчанию. Настроить этот путь с помощью:
** Системное свойство `keycloak.password.blacklists.path`.
** Свойство `blacklistsPath` конфигурации политики `passwordBlacklist` SPI. Чтобы настроить папку черный список, используйте `+--spi-password-policy--password-blacklist--blacklists-path=/path/to/blacklistsFolder+`.
* Черный список загружается автоматически при изменении списка.
** Этот файл проверяется на наличие обновлений во время проверки политики паролей, но не раз в 60 секунд. Используйте `+--spi-password-policy--password-blacklist--check-interval-seconds=<seconds>+` для изменения по умолчанию (0 для отключения).
** Файл черного списка должен быть обновлен точечно (записать в временный файл, а затем переименовать), чтобы избежать чтения частично записанного файла.

Текущая реализация использует BloomFilter для быстрой и эффективной проверки памяти, например, если данный пароль содержится в черном списке, с возможностью ложных срабатываний.

* По умолчанию используется ложная вероятность «0.01%».
* Для изменения ложной вероятности использования CLI используйте `+--spi-password-policy--password-blacklist--false-positive-probability=0.00001+`.

Для больших файлов из списка denylist {project_name} формирует фильтр цветов из текстового файла при каждом запуске или перезагрузке, который может занять несколько секунд.
Чтобы уменьшить время загрузки в миллисекунды, предварительно вычислите фильтр Bloom один раз, используя команду `build-password-denylist` CLI:

[source,bash]
----
bin/kc.sh tools build-password-denylist /path/to/100k_passwords
----

Это создает файл `100k_passwords.bloom` рядом с входным файлом.
Поместите его в папку password-blacklists и настройте политику паролей реалма на использование имени файла `.bloom` (например, `100k_passwords.bloom`) вместо текстового файла.
{project_name} определяет тип файла расширением: файлы, заканчивающиеся `.bloom`, загружаются как предварительно вычисленные файлы фильтров Bloom; все остальные файлы читаются как обычный текст.
Перезапустите команду и обновите значение политики каждый раз при обновлении списка denylist.

Вы также можете контролировать ложную вероятность попадания предварительно рассчитанного фильтра:

[source,bash]
----
bin/kc.sh tools build-password-denylist /path/to/100k_passwords --fpp 0.00001
----

[[maximum-authentication-age]]
===== Максимальный возраст аутентификации

Определяет максимальный возраст аутентификации пользователя в секундах, с помощью которых пользователь может обновить пароль без повторной аутентификации. Значение `0` указывает, что пользователь должен всегда повторно аутентифицироваться со своим текущим паролем, прежде чем он сможет обновить пароль.
См. <<con-aia-reauth_{context}, AIA section>> некоторые дополнительные сведения об этой политике.

NOTE: Возраст Максимальной аутентификации также настраивается при настройке необходимых действий *Обновить пароль* в вкладке *Требуемые действия* в консоли администратора. The better choice is to use  the
required action for the configuration because the _Maximum Authentication Age_ password policy might be deprecated/removed in the future.
