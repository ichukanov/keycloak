= Обработчики устранения неполадок

Когда рабочие процессы не ведут себя как ожидалось, логи сервера являются основным инструментом для понимания того, что происходит.
Двигатель рабочего процесса записывает подробную информацию о событиях жизненного цикла рабочего процесса, шагах и ошибках.

== Включение журнала отладки рабочего процесса

По умолчанию, движок рабочих процессов регистрирует предупреждения и ошибки. Чтобы увидеть полный поток выполнения, включите `DEBUG` уровень
для категории `org.keycloak.models.workflow`, установив следующий параметр конфигурации сервера:

    --log-level=org.keycloak.models.workflow:отладка

Это позволяет вести журнал отладки для движка рабочего процесса, всех поставщиков шагов и поставщика рабочих процессов.

== Что искать в логах

=== Активация и планирование рабочего процесса

Когда рабочий поток инициируется событием, движок регистрирует активацию и планирование первого шага:

* `Рабочий процесс'<name>активирован для ресурса <id> (исполнительный id: <id>)` — выполнение рабочего процесса было создано и обрабатывается.
* `Scheduled step <step> to run in <duration> for resource <id> (execution id: <id>)` — a scheduled step has been queued to run after the specified duration.

=== Шаг выполнения

По мере выполнения шагов, движок логает их прогресс:

* `Запуск шага <step> на ресурсе <id> (id исполнения: <id>)` — шаг скоро будет выполнен.
* `Step <step> completed successfully (execution id: <id>)` — the step finished without errors.
* `Workflow '<name>завершен для ресурса <id> (исполняющего id: <id>)` — все шаги в рабочем процессе были выполнены.

=== Ошибки и таймауты шага

Когда шаг потерпел неудачу или время исполнителя, движок регистрирует ошибку и запускает шаг с ошибкой. Шагом будет
повтор в следующем цикле выполнения (подробнее см. <_handling_failures_>>).

* `Step <step> failed (execution id: <id>) - сообщение об ошибке: <message>` — шаг бросил исключение во время выполнения.
* `Задержка исполнителя рабочего потока истекла во время выполнения шага <step>— исключение для выполнения шага с указанием на то, что шаг превысил установленный тайм-аут выполнения задачи. Смотрите <<_understanding_workflows_engine_>> , как настроить тайм-аут.
* `Исполнитель рабочего потока был отменен во время выполнения шага <step>— исключение для времени выполнения команды, указывающее на то, что сервис исполнителя был отменен по причине, отличной от тайм-аута.

=== Пропущенные и отмененные рабочие процессы

* `Пропуск рабочего процесса <name> как он отключен" — рабочий процесс отключен и не будет обрабатывать события.
* «Рабочий процесс»<name>отменен для ресурса <id> (исполняемого id: <id>)» — выполнение рабочего процесса было отменено.
* `Ресурс <id> больше не имеет права на рабочий процесс <name>. Отмена выполнения рабочего процесса.` — ресурс больше не соответствует условиям рабочего процесса после возобновления запланированного шага.

=== Ошибки рабочего процесса

* `Ошибка обработки события <event> для рабочего процесса <name>: <message>— ошибка при обработке события, вызывающего рабочий процесс.
* `Ошибка возобновления процесса <name> для ресурса <id>: <message>— ошибка при возобновлении запланированного выполнения рабочего процесса.
* `Could not find step <step> in workflow <name> for resource <id>. Отмена выполнения рабочего процесса.` — не удалось найти шага, запланированного на запуск.

=== Предупреждения на каждом уровне

Индивидуальные предупреждения поставщиков шагов, когда конфигурация отсутствует или недействительна. К примерам относятся:

* `Missing required configuration option '<key>' in <step>` — a required parameter was not provided in the step's `with` block.
* `Недопустимое требуемое действие <action> настроенное в <step>` — требуемое имя действия не распознано.
* `Пользователь <id> не имеет email-адреса, пропуска уведомления` — «notify-user» не удалось отправить письмо.
* `Не удалось отправить письмо с уведомлением на адрес <recipient>— произошла ошибка доставки электронной почты.

== Полезные категории журнала

Если вам нужно более целевое ведение журнала, вы можете включить ведение журнала отладки для конкретных компонентов:

[cols="2*", options="header"]
|===
|Категория
|Описание

|`org.keycloak.models.workflow` |Все журналы, связанные с рабочим процессом (движок, шаги, состояния)

|`org.keycloak.models.workflow.DefaultWorkflowProvider` |Жизненный цикл движка (активация, условия, обработка событий)

|`org.keycloak.models.workflow.RunWorkflowTask` |Шаг, выполнение, завершение, неудачи и таймауты

|`org.keycloak.models.workflow.ScheduleWorkflowTask` |Шаг планирования и отложенного выполнения
|===
