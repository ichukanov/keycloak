= Разрешить пользователям саморегистрацию

[role="_abstract"]
Вы можете использовать {project_name} в качестве стороннего сервера авторизации для управления пользователями приложений, включая пользователей, которые самостоятельно зарегистрировались. Если вы включите саморегистрацию, на странице входа отображается ссылка регистрации, чтобы пользователь мог создать учетную запись.

image:images/registration-link.png[]

Пользователь должен добавить данные профиля в регистрационную форму для завершения регистрации. Форма регистрации может быть настроена путем удаления или добавления полей, которые должны быть заполнены пользователем.

Даже если саморегистрации отключены, новые пользователи могут быть добавлены в {project_name} либо:

* Администратор может добавлять новых пользователей с использованием консоли администратора (или администратора REST API)
* При включении идентифицирующей брокерской услуги новые пользователи, авторизованные провайдером идентификации могут быть автоматически добавлены/зарегистрированы в хранилище {project_name}.
Смотрите <<_identity_broker_first_login, раздел Первого потока входа в систему в главе Identity Brokering >> .

Также пользователи, пришедшие из <_user-storage-federation, сторонние хранилища>> (например, LDAP) автоматически доступны в {project_name} , если включено определенное пользовательское хранилище

При включенной саморегистрации вместе с переключателем области *Проверьте почту* по электронной почте, пароль не будет установлен по умолчанию
в регистрационной форме. Пользователю сначала нужно будет подтвердить свой адрес электронной почты, и он сможет установить свой пароль на следующем экране. Рекомендуется
по соображениям безопасности, чтобы зарегистрированный пользователь после проверки электронной почты мог установить свой пароль или другие учетные данные. Обратите внимание, что также рекомендуется
включить <<enabling-forgot-password, Forget password>>, так что если пользователь не сможет проверить свой адрес электронной почты при саморегистрации, он может сделать это позже, подписавшись на
*Забыли пароль* поток, не будучи застрявшим.

If you still prefer to keep password on the initial registration form and make email verification to be done once user self-registers with his password, you can
setup the configuration option on the <<_authentication-flows,Registration authentication flow>>. Это можно сделать в консоли администратора, следуя закладке *Authentication* ->
поток *регистрации* (или другой поток, , который вы привязываете как регистрационный процесс) -> Настройки *проверки паролей* -> Включить *Всегда устанавливать пароль при регистрации.

Заметьте, что эта опция устарела и существует в основном для обратной совместимости. Она может быть удалена в будущем.
