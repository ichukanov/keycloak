== Использование внешнего накопителя

[role="_abstract"]
Организации могут иметь базы данных, пароли и другие учетные данные. Обычно вы не можете перенести хранилище существующих данных на развертывание {project_name} , так что {project_name} может объединить существующие внешние базы данных. {project_name} поддерживает LDAP и Active Directory, но вы можете кодировать расширения для любой пользовательской базы данных, используя SPI хранения пользователей {project_name}.

Когда пользователь пытается войти в систему, {project_name} проверяет хранилище этого пользователя, чтобы найти этого пользователя. Если {project_name} не находит пользователя, {project_name} итерацирует через каждого провайдера пользовательского хранилища в реалме до тех пор, пока не найдет совпадение. Данные из внешнего хранилища данных, затем сопоставляются в стандартную пользовательскую модель, потребляющую время выполнения {project_name}. После этого эта модель пользователя сопоставляет претензии токенов OIDC и атрибуты утверждения SAML.

Внешние базы данных пользователей редко имеют данные, необходимые для поддержки всех функций {project_name}, , чтобы поставщик пользовательского хранилища мог выбрать для хранения элементов локально в хранилище пользовательских данных {project_name}. Провайдеры могут периодически импортировать пользователей локально и синхронизировать с внешним хранилищем данных. Этот подход зависит от возможностей провайдера и конфигурации провайдера.  Например, ваше внешнее хранилище данных может не поддерживать OTP. OTP может обрабатываться и храниться {project_name}, в зависимости от провайдера.

=== Сбой в работе с провайдером

Если поставщик хранилища пользователей не сможет войти в систему и просмотреть пользователей в консоли администратора. {project_name} не обнаруживает сбои при использовании провайдера хранения данных для поиска пользователя, поэтому он отменяет вызов. Если у вас есть поставщик хранилища с высоким приоритетом, который не удается во время поиска пользователя, ошибка логина или запроса пользователя с исключением и не будет прервана до следующего сконфигурированного провайдера.

{project_name} ищет локальную базу данных пользователя {project_name} для разрешения пользователей перед любым провайдером LDAP или пользовательского хранилища. Рассмотрим вопрос о создании учетной записи администратора, хранящейся в локальной базе данных пользователя {project_name} в случае проблем с подключением к вашему LDAP и назад заканчивается.

Каждый LDAP и пользовательский поставщик хранилища пользователей имеет переключатель `enable` на странице консоли администратора. Отключение User Storage Provider пропускает провайдера при выполнении запросов, так что вы можете просматривать и входить в систему с учётными записями пользователя другого провайдера с более низким приоритетом. Если ваш провайдер использует стратегию импорта и отключен, импортированные пользователи по-прежнему доступны для поиска в режиме только чтения.

Когда сбой поиска провайдера хранения данных, {project_name} не сваливается из-за того, что базы данных пользователей часто имеют одинаковые имена пользователей или дублируют друг друга по электронной почте. Дублирование имен пользователей и электронных писем может вызвать проблемы, потому что пользователь загружается из одного внешнего хранилища данных, когда администратор ожидает, что он загрузит их из другого хранилища.
